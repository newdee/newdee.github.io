UnifyTerm，三个系统里同一个终端

2026-11-20 ·笔记 ·4522 字 ·约 11 分钟 ·阅读 次
Rust终端跨平台Agent

三台机器来回换，到了 Windows 这边每次都要重新想一遍：grep 装了没有，路径写 \ 还是 /，ls 是 PowerShell 的别名还是真的 ls。
UnifyTerm 想收掉这件事。它不做 shell，跑的还是你自己的 PowerShell、bash、zsh、fish，只把三个系统之间差掉的那层补上：99 个 Unix 命令跟着终端一起装（Linux 上 114 个），排在 PowerShell 的同名别名前面，路径一律用 / 打印。
命令历史连着目录、退出码和耗时存进一个 SQLite 文件，打字的时候就在下面列出来，拷到另一台机器接着用。图片、视频和 markdown 在终端里直接看。agent 那边给了 MCP 和一份 skill。

起因

写它的直接原因是换机器。macOS 和 Linux 之间换基本没感觉，一到 Windows 就得做选择题：装 Git Bash，开 WSL，或者记两套命令。前两条都是在终端外面再加一层东西，PATH、路径格式和权限模型跟着多一份；第三条最省事，代价是每条命令敲之前先想一下这是哪个系统。
第二件事是历史。换一台机器，前面攒的命令就没了。就算不换，Get-History 也只记得你敲过什么，不记得在哪个目录敲的，更不记得跑成没有、跑了多久。于是每次找一条命令都是翻完了再改目录。
第三件事是 agent。pane 里跑 Claude Code 或者 Codex 的时候，它得先试一遍才知道这台机器上有什么命令，试错都算在你的 token 上。
最早叫 uni-term，11 月 18 日改名 UnifyTerm，命令叫 ut。

命令

ut --list 把它带的命令都打出来，Windows 上 99 个，Linux 上 114 个（多出来的 15 个要 Unix 的属主、权限位、设备和登录信息）。版本号里也带着这个数：

命令本身是别人的，这一点得说在前面。coreutils 那 90 个是 uutils 的 crate，find 和 xargs 来自 uutils 的 findutils，sed 和 diff 同理，jq 是 jaq 的解释器套上 jq 的名字和选项，grep 是 ripgrep 的 searcher 和正则引擎下面补了 GNU grep 的选项、file:line:text 的输出和退出码。这个仓库里写的是选哪一个跑，加上 Windows 上缺的那层。
一个程序就是全部命令。启动时建一个链接目录，每个命令名一个链接指回同一个 exe，Unix 上是符号链接，Windows 上是硬链接（符号链接要的权限大多数人没有），跨盘了就退化成复制；这个目录放在 PATH 最前面。链接目录里存一份 .ut-links 清单，只有它列出来的名字会被删掉，不碰你自己放进去的东西。
PowerShell 那边还有一道。cat、cp、diff、dir、echo、kill、ls、mkdir、more、mv、pwd、rm、rmdir、sleep、sort、tee 这 16 个名字是 PowerShell 自己的别名或者函数，PATH 排再前也轮不到。启动脚本把它们挪开，一个会话做一次。剩下的名字（grep、sed、find、wc、jq 之类）PowerShell 没占，什么都不用做。
路径统一用 / 打印，pwd、find、realpath 都是。想要 Windows 原来的 \，设 UT_NATIVE_PATHS。有几个命令你更想要系统那个版本的话，commands.system = ["find", "sort"] 把它们留在原地。
没有 awk，也没有 rg。

通配符

这是 Windows 上最啰嗦的一块。Unix 下 *.txt 是 shell 在命令启动之前就换成文件名的，PowerShell 和 cmd 不做这件事，命令收到的就是 *.txt 四个字符。所以 Windows 上 ut 自己做：参数里有 *、? 或者 [...] 就换成匹配到的名字，按字节排序，一个都没匹配上就保持原样。
麻烦在引号。find . -name "*.rs" 这个引号是要留住的，cmd 会把引号原样传进来，看得见；PowerShell 在命令看到之前就吃掉了。于是 UnifyTerm 的 PowerShell 启动脚本改成在带引号的参数前面插一个私用区字符 U+E000，ut 这边把它取下来，后面的部分按原样用。文件名和选项都不会以这个字符开头，不会撞上。
agent 和脚本用 -Command 跑的命令不经过那个读入层，拿不到这个标记。所以那些一定是模式的选项，find 的 -name、-iname、-path、-regex 和 grep 的 --include、--exclude、--exclude-dir，它们的值永远按原样收，带不带引号都一样。别的地方要留住 *，就在同一行先设 $env:UT_NO_GLOB = '1'。
还有一层：find -exec、xargs、env 启动的程序中间没有 shell，参数本来就该按原样传过去。所以每个 ut 命令给自己启动的子进程设上 UT_NO_GLOB，免得展开两次。

出了窗口

命令只在 UnifyTerm 自己开的 shell 里有，这个限制撞上 keepane 就露出来了：keepane 的窗格是开机启动的那个服务端建的，不是 UnifyTerm 的子进程，PATH 和去别名两件事都没做过。
ut shell enable 管这个。它做三件事：在数据目录里生成 init.ps1、init.sh、init.fish；在每个 shell 的启动文件末尾（PowerShell 的 profile、.zshrc、.bashrc、fish 的 config.fish）加一段带标记的加载行；Windows 上再把链接目录放进用户 PATH 最前面，广播一次 WM_SETTINGCHANGE。disable 只删两行标记之间的东西，status 说在哪几个 shell 里开着。

已经开着的 shell 不会变，开个新的。
这一节踩的两脚都值得写下来。一是「启动脚本加载过没有」不能拿环境变量判断，环境变量会传给子进程，从 UnifyTerm 标签页里再开一个 pwsh 就会以为自己加载过了；改成会话变量才对，这条是 keepane 那边的 agent 指出来的。二是用户名带中文的时候，Windows PowerShell 5.1 读不带 BOM 的 init.ps1 会乱码，然后一声不吭地不加载；脚本加上 BOM 之后，第二次 enable 又认不出第一行的标记，在文件尾巴上追加了第二段。

历史

历史存成一个 SQLite 文件，两张表：命令文本存一次，记它跑过多少回、失败多少回；每次运行是另一张表的一行，记时间、目录、退出码、耗时和哪个 shell。

这些信息从 shell 的 OSC 133/633 标记来，各家说的不一样。PowerShell 的钩子说命令文本、退出码和提示符，不说「命令开始了」；bash、zsh、fish 全说；cmd.exe 只说提示符在哪。所以这边的规则是：命令从回车算起（133;C 先到就从它算），文本取 633;E 说的，没有就取回车那一刻输入行上的字，结束取 133;D，不说结束的 shell 就等到下一个提示符。
有三种命令不记：空格开头的（跟 bash 的 HISTCONTROL 一个意思，你自己标的）、看着带密钥的、超过 4096 字节的。认密钥用 11 条正则：名字里带 password、token、secret、api_key 一类词的赋值，--password x 这样的选项，Authorization: Bearer …，AKIA 开头的、ghp_、sk-、npm_、xox 开头的，JWT，URL 里的 user:pass@，还有 PEM 私钥的头。这些正则写得很宽，宁可多漏掉几条命令。送给模型的内容过的也是这一套。
打字的时候候选就在下面。召回走两条路：前缀那条读索引，表上建了首字符和前两个字符的生成列，一两个键就能从索引里直接按时间顺序取出来；打够三个字再加 FTS5 的 trigram 全文，这样命令中间的词也搜得到。两条各取最近 100 条，排序在 Rust 里算：前缀匹配 4 分，用得多的加 ln(1+次数)，新鲜度 2 分按七天半衰，在当前目录跑过的 1.5 分，失败过的按失败比例扣 2 分。所以进 backend 目录输入 cargo，先出来的是你在 backend 里跑过的那几条。
选中只是把命令填进输入行，不会替你按回车。
10 万条命令的库跑过一个性能测试，要求搜一次的 p95 低于 5 毫秒、写一条平均低于 2 毫秒，不达标测试就失败。库开了 WAL（窗口在写的时候 ut history 照样读）和 256 MB 的 mmap，写盘用 synchronous=NORMAL，程序崩了不丢，断电丢最后几条。

文件就一个 history.db，拷到另一台机器上接着用，三个系统读的是同一个格式。

纠错和解释

命令打错了有两层，第一层不联网。命令名不是任何已知程序、但离某个已知的只差一两个键的时候，直接给出那个：算的是编辑距离的变体，相邻两个字母对调也只算一步，所以 gti 到 git 是一步。四个字母以内的名字只许差一步，更长的许两步，kubctel get pods 能改成 kubectl get pods。名字本身认识的不管（git stauts 是 git 自己的事），带斜杠的路径不管。

第二层要模型，默认不配。ai.provider 填了 anthropic 或者 openai-compatible 之后，还要在窗口里点一次同意才真的开始用。送出去的东西窗口会原样列给你看：你正在打的这一行、当前目录（主目录写成 ~）、最近五条命令，命令没找到的时候再加上它打印的最后 40 行。发之前过一遍上面那套密钥正则。密钥本身不写进配置文件，ai.api_key_env 填的是放密钥的环境变量名。
开了之后 Ctrl-Shift-E 解释当前这行，每个参数一句；打字的时候后半截以灰色跟着，按 → 接受。

看图和文档

ut view 在终端里显示图片，挑哪种画法只看终端自己设的环境变量，不问终端也不读它的回答：

kitty 的图形协议：UnifyTerm 自己、kitty、WezTerm、ghostty
iTerm2 的内联图片：iTerm2
sixel：Windows Terminal
▀ 配两个真彩色：说自己有真彩色的终端
盲文点阵，一格 2×4 个点：UTF-8 终端
.:-=+*#%@：剩下的，以及输出不是终端的时候

UnifyTerm 自己实现的是 kitty 协议里的 Unicode 占位符那套：图片数据传过去之后，屏幕上写的是 U+10EEEE，前景色当图片编号，两个组合符标这一格对应图片的第几行第几列。好处是图片跟着文字滚动、进滚动历史、清屏就没了，跟一段文本没区别。
视频走 ffmpeg 解码，没有声音，q 或者 Ctrl-C 停。输出不是终端的时候给第一帧。
ut md 把 markdown 画成带样式的文字：标题加粗，代码和强调各有样式，列表和引用缩进，表格按显示宽度对齐（中文一个字两列），链接是终端超链接。读项目文档的时候不用再开浏览器。

给 agent 用

ut mcp 是个 MCP 服务端，走标准输入输出，给四个只读工具：history_search 查以前怎么做的，history_recent 查刚才跑了什么，list_commands 查这台机器上有哪些命令，command_help 查某个命令怎么用。注册一次：

它不提供执行命令的工具，这是故意的。Claude Code、Codex 自己都有 shell 工具，再给一套就有了两个执行入口，权限边界和上下文都要说两遍。所以这边只补环境知识，执行留给 agent 原来那条路。
另外有一份 skill，ut skill --install <目录> 装进去。它主要讲两件 agent 一定会撞上的事：agent 起的 PowerShell 通常带 -NoProfile，启动脚本没跑，那 16 个名字还是 PowerShell 的，要写 cat.exe 或者 ut cat；-Command 会在命令看到之前吃掉引号，要留住 * 得在同一行先设 UT_NO_GLOB。
Ctrl-Shift-A 打开右边的侧栏，读的是 keepane 的 list-agents -J：每个 agent 的模型、花了多少钱、上下文用了多少、CPU 和内存。只在侧栏显示的时候问，默认两秒一次，关掉就不问了。点一张卡片跳到那个 pane。

设置

设置是一个 config.toml，Windows 在 %APPDATA%\unifyterm，macOS 在 ~/Library/Application Support/unifyterm，Linux 在 ~/.config/unifyterm。现在 32 项，每项都可以不写。写错的项名和越界的值不会让程序起不来，第一个标签页顶上写一行说哪个不对，那一项用默认值。

ut setting 在标签页里打开上面这个界面，全程键盘：上下移动，回车改（开关直接翻，字体、shell、模型服务商这些弹一个列表挑，可以打字过滤），左右加减数字，e 手打任意值，d 恢复默认，u 撤销，/ 过滤，q 退出。不合法的值写不进去，那一行直接说为什么。你文件里的注释会留着。
文件一改就重读，不管是这个界面改的还是你拿编辑器改的。字体、颜色、内边距和候选列表立刻变；shell.* 和 terminal.scrollback 下个标签页生效；剩下的要重启。改坏了的文件什么都不会动，正在用的设置照旧，日志里写原因。
给脚本的是 ut setting list、get、set、reset、path。

几个坑

发出去之后在 V2EX 上收到的两条，都是我自己测不出来的那种。
第一条：Windows 安装包「安装一闪而过，快捷方式无效，无图标」。查出来是 VCRUNTIME140.dll。Rust 在 Windows 上默认动态链接 C 运行库，全新装的系统里没有这个 DLL，要等别的软件带一份 Visual C++ 运行库进来；开发机和 CI 上都有，所以两边都测不出来。改法是 .cargo/config.toml 里给 MSVC 目标开 +crt-static，把运行库链进程序，CI 加一步用 dumpbin 检查两个 exe 不依赖 VCRUNTIME*、MSVCP*、api-ms-win-crt-*，这一步对上一版的程序会失败（9 个）。代价是程序大了 0.2 MB。
第二条：开始菜单里的图标是一张白纸。MSI 建的是通告式快捷方式，目标和图标都指向 Windows Installer 缓存里一个没有扩展名的文件。上一版我写过「本机有图标、没能复现」，那是只看了会走缓存的那个界面，判断不对；读快捷方式本身才看见目标是 C:\WINDOWS\Installer\{…}\UnifyTermIcon。改成普通快捷方式直接指 exe，图标项带上 .ico 后缀，顺手把桌面图标也加上。
第三条是自己发现的：在 keepane 里切了窗口之后，键盘不在 UnifyTerm 上，要用鼠标点一下。keepane 的客户端调的是 SetForegroundWindow(GetConsoleWindow())，而在 UnifyTerm 里这个「控制台窗口」是 ConPTY 的伪窗口，0×0，没有所有者，于是前台落在一个看不见的窗口上。Windows Terminal 给伪窗口设了所有者所以没事，ConPTY 这边设不了。修法收在一处：窗口失去激活的时候，如果前台是自己子进程的伪控制台窗口，就把激活抢回来，别人的窗口一概不碰。

边界

安装包还没签名，Windows 的 SmartScreen 和 macOS 的 Gatekeeper 各拦一次
macOS 上 CI 能构建、能起、能跑测试，真机上过了手，但用得还少
视频没有声音，而且要系统里装了 ffmpeg
UnifyTerm 自己画的是 kitty 的图形协议，sixel 和 iTerm2 那两种是 ut view 输出给别的终端用的
PowerShell 的 Tab 补全还是补出 \ 的路径
自己的 shell 另开了一个项目（UnifyShell，命令 ush），现在还没开工

和 keepane

本来想在这里面做消息和可观测两块，想了一轮之后放弃了：逐条对照下来，keepane 已经都有。pane 之间发消息、两台机器之间转发、手机上看、agent 的花费和 trace、总览界面，全在那边。
所以分工是这样：keepane 管多窗格、agent、通信和可观测，UnifyTerm 只做跨平台的 GUI 终端。侧栏保留着，但不往「把 keepane 的数据再画一遍」这个方向加东西，想加的加到 keepane 里。两个程序各自独立，一起用也行。

装和用

macOS 和 Linux 走 Homebrew：

Homebrew 6 之后，非自家 tap 的 formula 要先信任一次才能用短名字，brew trust --formula newdee/tap/unifyterm 信任这一个。不想用 Homebrew 的话有一行安装脚本，装进 ~/.local/bin，不要 root。
Windows 走 Scoop：

或者 irm https://raw.githubusercontent.com/newdee/unifyterm/main/install.ps1 | iex，装进 %LOCALAPPDATA%，不要管理员权限。Release 页面上另有 MSI、zip、dmg、deb、AppImage 和 tar.gz，每个旁边一个 .sha256。Linux 上窗口要 Vulkan 和 xkbcommon，Debian 系装 mesa-vulkan-drivers libxkbcommon-x11-0。
装完直接 unifyterm 起窗口。想在别的终端、keepane 的窗格、agent 的 shell 里也用这些命令，跑一次 ut shell enable。

实现

Rust 写的，GUI 用 GPUI（Zed 那套），一个标签页一个伪终端，Windows 上走 ConPTY。代码分成几块：ut 是命令和它们的 Windows 适配层，history 是那个 SQLite 库，config 管设置和生成启动脚本（窗口和 ut shell 用同一份），assist 管纠错和模型，窗口本身在 unifyterm 里。
实机检查靠回放做到可复现：UNIFYTERM_RAW_LOG 把第一个标签页收到的每个字节追加进文件，unifyterm --replay <文件> 把它们重新画一遍。同一份录制回放六次，屏幕哈希完全相同，所以截图比对才敢当成测试用；GPU 混色的舍入会偶尔差 1/255，那一处留了 2/255 的容差。
剩下的都在 README 和项目页里。写到这儿发现，这篇里真正属于我自己的代码没多少，大半是把别人写好的命令摆到 Windows 上该在的位置，也挺好。
