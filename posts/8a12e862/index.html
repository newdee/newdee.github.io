UnifyTerm: 跨平台统一终端

2026-11-20 ·笔记 ·3590 字 ·约 9 分钟 ·阅读 次
Rust终端跨平台Agent

UnifyTerm 是一个用 Rust 和 GPUI 开发的跨平台终端，支持 Windows、macOS 和 Linux。
它保留系统 Shell，另外提供一套常用 Unix 命令、按目录检索的命令历史，以及供 Agent 查询环境的 MCP 接口。

这里主要记录命令兼容、历史采集和 Agent 接入的实现与限制。源码和项目主页在此。

命令环境

跨平台使用 Shell，最先遇到的往往是命令差异。同一句 grep -rn "TODO" ./src，在 Linux 上能执行，到了没有安装相应工具的 Windows 环境就得换一种写法。即使补齐可执行文件，还要处理 PowerShell 别名、路径格式和通配符展开。

UnifyTerm 将常用命令合并到 ut 中，随程序一起分发。本文对应版本在 Windows 上提供 99 个命令，Linux 上提供 114 个，包含 cat、ls、pwd、grep、find、sed、sort、jq、diff、xargs 和 which。完整清单可以用 ut --list 查看。

这些命令复用了已有实现：coreutils 来自 uutils，find、xargs、sed 和 diff 使用对应的 uutils 项目，jq 使用 jaq，grep 使用 ripgrep 的搜索与正则引擎，再补齐 GNU grep 的选项、输出格式和退出码。UnifyTerm 负责统一入口，并处理各系统的运行差异。

Shell 仍使用原来的 PowerShell、CMD、Bash、Zsh 或 Fish，原有配置和启动脚本继续生效。需要分清两个层次：ut 提供的是命令，变量展开、管道和重定向等语法仍由当前 Shell 解释。

PowerShell 别名

PowerShell 查找命令时会先检查别名和函数，单把命令目录放到 PATH 前面不够。例如输入 cat，仍可能调用 Get-Content。

UnifyTerm 的启动脚本会在每个会话里移开 16 个冲突名称：cat、cp、diff、dir、echo、kill、ls、mkdir、more、mv、pwd、rm、rmdir、sleep、sort、tee。grep、sed、find、wc、jq 等没有相应冲突，无须处理。

Agent 经常用 -NoProfile 启动 PowerShell，此时启动脚本不会执行。遇到这些同名命令，应显式写 cat.exe 或 ut cat，不能假定交互窗口里的命令解析结果也适用于 Agent 的 Shell。

路径与通配符

Windows 下的内置命令可以接收 C:/Users/developer/project 这样的路径，默认也用 / 输出路径。PowerShell 自己的 Tab 补全仍可能产生反斜杠，Windows 原生程序的路径行为也不由 ut 控制。

通配符需要单独处理。Unix Shell 通常在启动命令前展开 *.txt；PowerShell 和 CMD 启动原生命令时不会做同样的展开，因此 Windows 上由 ut 补上这一层。

但 find . -name "*.rs" 中的 *.rs 应当交给 find 解释，不能先展开成文件列表。CMD 会保留引号，PowerShell 却会提前去掉，UnifyTerm 因而在 PowerShell 启动脚本中用私用区字符 U+E000 标记带引号参数。ut 收到参数后移除标记，并保留其字面内容。

通过 -Command 执行的命令不经过这层标记。对于 find 的 -name、-iname、-path、-regex，以及 grep 的 --include、--exclude，ut 将选项值直接视为模式。其他位置需要保留 * 时，可以先在同一行设置 $env:UT_NO_GLOB = '1'。

接入其他 Shell

命令集也能在 UnifyTerm 窗口外使用：

enable 在数据目录生成各 Shell 的启动脚本，并在启动文件末尾插入带标记的加载段；disable 只移除标记范围内的内容。Windows 上还会把命令目录放到用户 PATH 前面，并广播 WM_SETTINGCHANGE。启用后需要重新打开 Shell，已有进程不会因此更新自己的环境。

Keepane 的 Pane 由后台服务创建，不是 UnifyTerm 的子进程，无法直接继承窗口内的 PATH 与别名处理。将命令集接入 Shell，正是为这类独立启动的会话准备的。

历史采集

UnifyTerm 用本地 SQLite 保存命令、工作目录、退出码和耗时。例如同一条 cargo test，在什么项目中运行、上次是否成功，都会成为后续检索的条件。

采集依赖 Shell 的 OSC 133/633 标记，但各 Shell 报告的信息并不相同。PowerShell 钩子提供命令文本、退出码和提示符，没有独立的开始通知；Bash、Zsh、Fish 的标记较完整；CMD 只报告提示符位置。

因此，开始时间取用户按回车的时刻，或先到达的 133;C；命令文本取 633;E；结束取 133;D。没有结束标记时，等下一次提示符出现再结束计时。历史中的耗时来自这套边界判断，不宜当作精确的性能测量。

检索与排序

输入命令时，下方显示历史候选，并提高当前目录中常用命令的排序。

召回先走前缀索引，表上为首字符、前两个字符建立了生成列。输入达到三个字符后，再加入 FTS5 trigram 全文检索。候选的排序在 Rust 中完成，使用固定权重：

前缀匹配加 4 分；使用频次加 ln(1+次数)。
新鲜度最多加 2 分，按 7 天半衰。
曾在当前目录执行加 1.5 分；失败记录按失败比例最多扣 2 分。

这里选择可解释的固定评分，目录、频次和执行结果怎样影响排序都可以直接检查。仓库中的性能测试使用十万条历史，要求搜索 p95 低于 5 毫秒、单条写入平均低于 2 毫秒；这是测试的验收阈值，具体机器上的结果仍需实测。

候选列表用 Ctrl-N / ↓ 和 Ctrl-P / ↑ 移动，Tab 或 Enter 将选中项填入输入行，Esc 关闭列表。选择候选不会直接执行命令，还需要确认输入。

存储与迁移

数据库文件名为 history.db，开启 WAL 和 256 MB 内存映射。WAL 允许终端窗口写入历史时，ut history 继续读取；synchronous=NORMAL 在写入开销与掉电持久性之间取折中，断电可能丢失最近尚未同步的提交。

历史数据不依赖某一种 Shell 的历史文件格式，可以在 Windows、macOS 和 Linux 间迁移。不过跨系统迁移的是记录，原记录中的目录和命令不一定在目标系统上有效。备份使用 WAL 的数据库时，也要处理仍在 WAL 中的提交，不能把运行中的主数据库文件简单视为完整快照。

记录过滤

历史可能包含访问令牌或密码，保存前会跳过以下命令：

以空格开头：由用户主动标记不留历史。
命中密钥特征：整条跳过。
长度超过 4096 字节：不保存。

密钥检测使用 11 条正则，覆盖名称包含 password、token、secret、api_key 的赋值，--password 一类选项，Bearer 认证头，常见服务的密钥前缀，JWT，URL 中的 user:pass@ 和 PEM 私钥头。规则较宽，可能漏记正常命令，也不能保证识别所有敏感内容。历史仍应当作为本地私有数据管理。

图片与文档

ut view 用于查看图片和视频，ut md 用于阅读 Markdown：

图片显示使用 Kitty Graphics Protocol 的 Unicode 占位符方式。先传输图片数据，再在终端网格中写入 U+10EEEE：前景色编码图片编号，两个组合符标记图片对应的行列。图片因而能随终端文字滚动、进入滚动历史，并在清屏时移除。

在其他终端中运行 ut view，程序根据终端环境选择输出协议：iTerm2 使用内联图片协议，Windows Terminal 使用 sixel，其余环境再依次退化为半块字符、盲文点阵或 ASCII。实际显示效果取决于宿主终端支持的协议。

视频由外部 FFmpeg 解码，当前只显示画面，没有声音；需要事先安装 FFmpeg。ut md 将标题、列表、表格和链接转换成终端样式，适合在命令执行间隙查看文档。

命令辅助

本地纠错和模型辅助分别配置。前者检查当前机器上的命令名，不发网络请求；后者支持 Anthropic 和 OpenAI-compatible 接口，需要用户配置并确认后启用。

本地纠错

命令名不存在时，程序用允许相邻字符交换的编辑距离寻找候选。gti 到 git 只算一步；四个字符以内的名字最多允许一步，更长的名字允许两步，例如将 kubctel 提示为 kubectl。

它只处理命令名。git stauts 中的 git 本身存在，因此不会修改子命令；带路径分隔符的名字也不处理。这个范围可以避免把显式指定的程序路径当作拼写错误。

模型请求

模型辅助包括纠错、解释和输入补全。Ctrl-Shift-E 解释当前命令，输入时也可以显示灰色的后续建议。

请求的上下文范围会在启用确认时列出：当前输入行、将主目录缩写为 ~ 的工作目录，以及最近五条命令；命令未找到时，另附其最后 40 行输出。发送前会过滤识别出的敏感信息。

配置中的 ai.api_key_env 保存密钥所在的环境变量名，密钥本身不写入配置文件。默认没有模型提供商配置。启用外部服务后，列出的上下文会发送到对应服务，是否接受这一范围需要用户自行决定。

Agent 接入

UnifyTerm 向 Agent 提供命令清单、帮助与历史，执行仍使用 Agent 原有的 Shell 工具。这样可以复用原有执行权限和工作目录，不再增加第二套命令执行入口。

Ctrl-Shift-A 打开 Agent 侧栏，读取 Keepane 提供的模型、Token 费用、上下文占用、CPU 和内存信息。显示时默认每两秒刷新，关闭后停止轮询。

UnifyTerm 与 Keepane 可以独立使用。前者负责终端窗口、命令集、历史与内容显示，后者负责 Pane 生命周期、消息和多 Agent 协作。Keepane 的介绍另有一篇。

使用限制

统一命令集并不等于统一全部系统行为。Shell 语法、Windows 原生程序以及系统权限仍遵循所在环境；当前命令集也没有 awk 和 rg，需要按任务选用 grep、sed、jq 或 cut 等工具。

多媒体部分的视频没有音频，图片效果受终端协议支持影响。本文对应发布的构建产物尚未签名，macOS 虽有 CI 构建与启动检查，手动验证仍不充分。安装和部署到日常环境前，这几处要分别确认。

命令历史、MCP 和模型辅助也有不同的数据范围：历史保存在本机，MCP 可向接入的 Agent 返回历史，启用模型辅助后则会向配置的服务发送指定上下文。敏感内容过滤只能降低误存、误发的概率，不能代替使用者检查。

跨系统脚本能少改几次命令，才算这层兼容有用。
