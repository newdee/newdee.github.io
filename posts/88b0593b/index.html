magpie 本地语义搜索

2026-08-21 ·笔记 ·3832 字 ·约 10 分钟 ·阅读 次
RustTauri工具

星标过的仓库再也没打开过第二次，截图知道长什么样却翻不到，书签埋在几层文件夹里，这些东西的共同点是存的时候很顺手、找的时候全靠运气。
喜鹊爱叼亮闪闪的东西回窝，然后忘了放哪儿，所以叫 magpie。按一下 Alt+Space，把还记得的那点描述打进去，或者直接丢一张图进去，回车。
本地跑，不联网，不扫全盘。

三个源

Tab 在三个源之间切，每个源有自己的索引方式和自己的排序选项。

本地文件

你手动加进来的目录，里面每个文件都能按名字找到；认识的格式连内容一起进全文索引。

约八十种纯文本与代码格式，整篇读进去，默认单文件上限 4 MB，设置里可以调到 16、64 或者不限
PDF 走 pdf-inspector 抽文字，上限 64 MB；扫描件和乱码的抽不出来，仍然按文件名留在索引里
docx / xlsx / pptx 当 zip 拆开，把带文字的 XML 部分挑出来去标记
视频、压缩包、二进制这些，只索引文件名
图片不走文本，单独交给视觉模型

Shift+Tab 在「全部 / 文本 / 图片」三个范围之间切，找图的时候把文档滤掉，找代码的时候把图滤掉。

GitHub 星标

贴一个不需要任何 scope 的 token，整份星标列表同步下来：名字、描述、topics，加上完整 README。

每次同步都会把星标列表整个拉一遍，十页一千条，不贵，而且这是唯一能可靠发现「取消星标」的办法——增量接口不会告诉你少了什么。README 的抓取带 ETag 做条件请求，服务端回 304 就不传正文。判断哪些仓库需要重新抓，看的是 pushed_at 有没有变过。这里有个小设计：记录里存的「上次抓取时的 pushed_at」同时兼任「抓过了」的标记，所以一个根本没有 README、返回 404 的仓库，也会被记成已处理，不会每次同步都去白请求一遍；等它真的有了新提交，标记对不上了才重试。

排序有三种，相关度、星标时间、星数，Shift+Tab 循环。这里有个容易做错的地方：按星数排的时候，重排的只是已经命中的前若干条，不是把候选池放宽再排。不然一搜就是一堆万星但跟你查的东西没关系的仓库挤在前面。每行还显示最后推送时间，荒废的项目一眼能看出来。

浏览器书签

直接读本地的书签文件——Chromium 系的是 JSON，Firefox 是 places.sqlite——不走浏览器 API，不需要登录，不联网。

Chrome、Edge、Brave 这些走固定路径，但分支太多了，硬编码一张清单迟早漏。所以还会扫一遍平台的数据根目录，凡是磁盘布局长得像 Chromium 的（有 Default 或 Profile * 目录、里面有 Bookmarks 文件）就认，Vivaldi、Arc 以及各种小众分支不用我一个个加。所有 profile 一起读，按标题、网址和所在文件夹路径搜，语义匹配叠在上面。

索引

遍历用的是 ignore 那个 crate 的 walker，几个开关是刻意拧的：不跟符号链接、跳过隐藏文件、.gitignore 生效——而且是 require_git(false)，也就是说哪怕那个目录根本不是 git 仓库，里面的 .gitignore 照样算数。很多人的工作目录就是这样，规则文件在，.git 不在。

读之前先嗅探。前 8 KB 里出现 NUL 就当二进制处理，不往全文索引里灌乱码——扩展名不可靠，一个 .log 完全可能是二进制。

改动检测分两层，因为两件事的代价差得远。扫描这一层看 mtime 和大小，都没变就直接跳过、连文件都不打开；嵌入那一层算一个 FNV-1a 哈希，把文件名、路径和正文一起哈进去，值没变就不重算向量。所以文件被 touch 了一下、或者移动过又移回来，扫描会重新读它，但模型不会被惊动。图片没有正文可哈，用的是路径、mtime、大小三样拼起来的指纹。磁盘上消失的文件按路径反查删掉，不会在索引里留幽灵条目。

三个触发时机：启动时扫一遍，手动刷新扫一遍，还有每三十分钟一次的定时器。

全文索引这块用的是 FTS5 的外部内容表，正文只存在原表里，FTS 只存倒排结构，不留第二份副本；增删改由触发器同步，业务代码里没有一处需要记得「哦这里还要更新索引」。删掉一个目录的时候，文件行、全文索引、向量靠外键级联和触发器一起消失，不需要手写清理逻辑——这也是「删除即彻底删除」这个承诺能兑现的原因。

检索

两路怎么合

关键词一路，语义一路，各取前五十条候选，然后按名次融合。

选倒数排名融合而不是加权求和，原因是 BM25 的分数和余弦相似度不是一个量纲。BM25 的取值范围跟语料规模、词频分布都有关系，余弦老老实实在 −1 到 1 之间，把两个数直接加权相加，那个系数只能靠拍脑袋定，换一批语料就得重调。倒数排名融合只吃名次：每条结果在每一路里的名次 r，贡献 1 / (60 + r + 1)，几路加起来。两路都靠前的会被抬上来，只在一路里出现的也不会被埋掉。

余弦值没有被丢掉，但只以 0.005 的权重叠在融合分上。这个量级是刻意的——它只够在两条名次相同的结果之间破个平局，不足以改变名次结构本身。

跨语言是白送的。e5 是多语言模型，中文查询能命中英文 README 和代码注释，反过来也行，一百多种语言。

关键词那一路

SQLite 的 FTS5，unicode61 分词。查询串会被重新组装一遍：按空白切成词，每个词加引号再加 * 做前缀匹配，然后用 AND 串起来。前缀匹配是为了边打字边出结果——打到 embed 的时候 embedding 已经能命中了。

BM25 是带列权重的，星标那张表里名字给 8.0、描述和 topics 给 4.0、README 给 1.0。仓库名里出现的词，分量是 README 正文里出现的八倍，这跟人的直觉一致：你打出一个词当仓库名的时候，通常就是在找那个仓库。

命中会带一段上下文摘要，取命中处前后十二个词的窗口，两头带省略号，命中的词高亮。实现上是 FTS5 的 snippet 把匹配区间包在 \u{1} 和 \u{2} 两个哨兵字符里，前端再把哨兵换成高亮标记——比让 SQL 直接吐 HTML 干净，也不用担心正文里的尖括号被当成标签。图片那类行没有正文，snippet 会返回 NULL，所以这段是可有可无的，没有就只显示文件名。

长文与分块

长内容切块，每块约 1600 字符、重叠 200 字符，一块一个向量，一个文件最多 128 块。切的时候优先在换行处断，不硬切在句子中间。

检索的时候一个文件按它最好的那一块算分。这条对两类东西特别重要：一是长文档，一句话埋在第一百页里也捞得出来，不会因为整篇平均下来相关度低而沉底；二是 README 很长的仓库，整体稀释会让它输给一个只有三行说明但恰好词对上的小项目。

README 那边还多做一步：每一块前面都会贴上仓库的「身份头」——全名、描述、topics、语言。因为切开之后，中间某一块可能通篇在讲某个 API 的参数，孤零零拿出来根本看不出属于哪个项目，贴上头之后每一块都是可归属的。嵌入之前 README 还会洗一遍，徽章、图片、HTML 标签、链接地址全去掉（链接文字留着），代码围栏整段丢掉——代码带来的是噪声不是语义。

e5 这个模型要求查询和文档分别加 query: 和 passage: 前缀，这不是可选的风格，前缀错了向量空间就对不上。

向量放在内存里

向量不是每次查询去库里读，是全部常驻内存。分块之后一次按键要读几十 MB，边打字边查撑不住。

存的形式很朴素：L2 归一化过的 f32 数组，当 BLOB 塞在 SQLite 里。归一化在生成时就做完了，所以算相似度就是一次点积，没有开方也没有除法。几万块全量暴力算是十几毫秒的事，召回率 100%，省掉一整套近似索引和它带来的调参、重建、召回率折损。真到撑不住那天，sqlite-vec 落进同一个文件就行，不用换存储。

文字和图片是两个向量空间，但它们的 id 集合天然不相交——一个文件要么是图片要么是文本——所以两路相似度不会混在一起比大小。

模型没就绪也能用。查询向量在代码里是可空的，没有就只走关键词那一路。首次启动要下大约 700 MB 模型，这段时间搜索照常出结果，不是转圈等。设置里可以把下载源换成 hf-mirror.com，直连 HuggingFace 不通的网络下有用。

图片

图片用 SigLIP 2 嵌入，文字和图片在同一个空间里，所以两个方向都通。

文字找图——打「海边日落」，或者任何语言的同义描述，匹配的照片和别的结果一起排出来，带缩略图
图找图——把图拖进面板、粘贴一张截图，或者点选图按钮，返回最相似的若干张，带余弦相似度百分比

这块没用现成的封装。fastembed 的 ImageEmbedding 对三维输出默认按 CLS token 池化，而 SigLIP 用的是 MAP head、根本没有 CLS token，套上去出来的向量是错的——不会报错，只是结果一直不对，这种 bug 最难发现。所以这一层自己持有两个 ONNX session、自己做图像预处理和输出选择，池化键按 pooler_output、text_embeds、image_embeds 的顺序去找。文本侧固定 64 token，SigLIP 就是按这个长度训的。

图片向量上带着模型标识，换了模型或者换了权重文件，旧向量自动作废重算，不会留下两个空间里的向量混在一起比大小。损坏读不出来的图片会打一个零维标记，下次不再重试，也不会因为一张坏图卡住整轮索引。

缩略图是 96 像素的 JPEG，存在文件行里，结果列表直接用；拖进来的查询图也生成一张预览，但那张不存。

只读你指定的目录

这条是靠结构保证的，不是靠承诺。

magpie 只索引你显式添加的目录，指向你的工作目录，别的地方一个字节都不会读。目录内递归，但隐藏文件跳过、.gitignore 生效、符号链接不跟出所选目录。加目录的时候会挡住嵌套和重复——不然两个目录互相包含，同一个文件会进两次索引，删其中一个的时候另一个的记录也跟着乱。

索引就是用户目录下的一个 SQLite 文件。嵌入模型走 ONNX 本地跑，一次性下载完之后整个东西离线可用。书签直接读本地文件。没有任何东西发出去。

设置里能看到到底索引了哪些目录，删掉一个，它的文件记录、全文索引、向量一起抹掉。每个目录和星标索引都有单独的重建按钮，怀疑哪块索引坏了就单独重建，不用推倒整个库。

还有一条不太显眼的：回车「打开文件」这个动作，先校验路径确实落在某个已注册目录里面，不在就直接拒掉；通过之后也只是在资源管理器或访达里把它定位出来，不是执行它。搜索结果本来就是从自己的库里出来的，这两道其实是冗余的，但一个搜索工具最不该做的事就是替你运行一个你只是想找到的文件。

用法

从 Releases 拿构建：Windows 的 NSIS 安装包，macOS 的 dmg（Apple Silicon），Linux 的 AppImage/deb/rpm。

macOS 的包没签名，从浏览器下 dmg 会被 Gatekeeper 拦。用 curl 装可以完全绕开隔离属性：

已经拦下了的话，右键「打开」，或者 xattr -cr /Applications/magpie.app。

自己编译：

要 Rust、Node 加 pnpm，以及 WebView2 或 WebKit 运行时（Windows 11 和 macOS 自带）。

键位就这些：

Alt+Space 唤出或收起，可以在设置里录一个别的
↑ ↓ 与 PgUp PgDn 翻结果
Enter 打开：仓库和书签进浏览器，文件在资源管理器或访达里定位
Ctrl+Enter 把输入交给浏览器，像网址就直接开，否则搜一下
Tab 换源，Shift+Tab 切本地范围或星标排序
Esc 依次清掉图片查询、关设置、收窗口
拖入、粘贴或点选一张图，进入以图搜图

面板停在屏幕上方居中，压在所有窗口之上，失焦不隐藏——不然拖放就没法用了，拖标签条可以挪位置。空查询的时候本地源列最近的文件，星标源列最近标的仓库，当个浏览视图用。

设置里还有：GitHub token 和连接状态、索引目录的增删与重建、外观（跟随系统/浅色/深色）、唤出快捷键、模型下载源、单文件大小上限、模型下载进度、版本号。

限制

扫描件 PDF 和截图里的文字现在读不出来，那种 PDF 只能按文件名找到，OCR 还没做。
没有预览面板，命中之后只能开出去看。
macOS 的包没签名也没公证，装的时候要多一步。
向量是暴力算的，几万块没问题，真堆到几十万得换检索结构。
Twitter 的喜欢想做，但只能走数据导出的归档文件，官方 API 现在要钱。

代码是 MIT，Rust 核心在 core/，Tauri 壳很薄，前端就一个窗口。起因是星标列表只能按名字搜，而人记得住的通常是「那个用 Rust 写的、干什么用的东西」，偏偏就是想不起来叫什么。现在把那句话打进去能出来，暂时就够用了。
