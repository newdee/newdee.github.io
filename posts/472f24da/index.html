LEANN 的重算式向量索引

2026-08-31 ·笔记 ·1408 字 ·约 4 分钟 ·阅读 次
检索架构Python

LEANN 通过检索时重算向量，减少近邻索引的磁盘占用。
其 HNSW 后端只保留图结构，遍历到候选节点时再读取原文、计算嵌入；DiskANN 后端则保留压缩向量用于导航。
两条路径都将一部分离线存储成本转移到在线计算。这篇按论文与仓库实现说明这种取舍。

存储开销

向量的存储需求随条数、维度和精度增长。一条 768 维 float32 向量占 3072 字节，六千万条仅原始向量就约 184 GB，尚未计算图连接与其他元数据。

LEANN 将完整向量从持久索引中移除，需要时再从文本计算。项目给出的对比包括：

六千万条维基文本：201 GB 对 6 GB。
两百一十万条 DPR：3.8 GB 对 324 MB。
七十八万封邮件：2.4 GB 对 79 MB。
三万八千条浏览记录：130 MB 对 6.4 MB。

这些是项目自报数据，本文没有复现。嵌入维度、模型、硬件与基线索引配置都会影响结果，个人数据两组也不能直接代表公开数据集。复现实验的入口是 benchmarks/run_evaluation.py，会下载评测数据。

检索流程

查询先生成嵌入，再进入近邻图遍历。每到一组候选节点，后端提交节点编号，嵌入服务读取原文并计算候选向量，距离结果返回后，图遍历才继续。

C++ 后端基于 faiss 和 DiskANN 的分叉，使用 ZeroMQ 与 Python 嵌入进程通信，节点编号编码在 protobuf 中。Python 侧负责原文读取与批量嵌入，相关通信依赖还包括 msgpack。

这使嵌入推理和进程往返进入查询路径。为控制成本，邻居请求要合批，两级搜索先筛选再精算，图剪枝则减少需要访问的候选。是否节省磁盘，要与一次查询实际重算多少节点、每批推理延迟一起衡量。

图剪枝

删除向量后，图的邻接表仍占空间。LEANN 使用高度数保留剪枝，保留承担连通作用的枢纽节点，裁去冗余连接，再用压缩稀疏行格式保存图。

剪枝同时影响存储和检索：边少了，邻接表更小，重算请求也可能减少；裁得过多则可能拉长路径或损失召回。不能只比较图文件大小，还需要在相同精度要求下测量访问节点数和查询延迟。

后端

HNSW 路径采用完全重算，持久索引不保存向量。DiskANN 路径保留乘积量化后的向量用于图导航，只在需要精确距离时重算，因此在线推理与通信次数可以减少，但索引占用会增加。

两者适用于不同约束：前者优先降低磁盘占用，后者在空间、延迟和精度之间留出折中。项目文档更推荐后者的综合表现，实际选择仍需按自己的语料测试。

参数

检索侧的默认值摆在 api.py 里：候选队列 complexity=64、beam_width=1、prune_ratio=0.0、recompute_embeddings=True，剪枝策略默认 global，另有 local 和 proportional 两档。

recompute_embeddings 可以关，关掉就退回普通的存向量模式，这在索引不大、又想要极限延迟的时候有意义。剪枝比率默认是零，也就是不额外剪，需要更省的时候再往上调。

顺带一提它还带一条 BM25 通路，用 SQLite 的 FTS5 建全文索引，和向量结果做融合，分词那里对中日韩做了 ngram 处理。这条跟主线关系不大，但对中文语料是实打实的差别。

仓库提供的接入包括：文件系统、Apple Mail、浏览器历史、微信、iMessage、ChatGPT 与 Claude 的会话记录、Slack、Twitter 书签。另有 MCP 服务，可向 Claude Code 等客户端提供基于索引的检索。

生成模型那侧支持本地引擎（Ollama、vLLM 之类）和云端 API 两种，README 的推荐是本地，理由跟整个项目一致，数据不出机器。

代价

重算要求嵌入模型在查询时可用。启动服务时要加载模型，查询时要承担推理和跨进程通信；部署容量因此既包括磁盘，也包括计算资源与模型冷启动时间。是否需要 GPU、需要多大吞吐，取决于所选模型和负载。

论文中 RAG 场景的延迟“可比”，不能据此推出独立检索更快。端到端 RAG 包含生成耗时，检索增加的时间可能被弱化；交互检索仍应单独测量查询分位延迟。

算法实现在 yichuan-w/faiss 和 yichuan-w/DiskANN 子模块，主仓库负责 Python 编排。排查重算与遍历开销时，需要把这两部分一起拉取。

个人文档、邮件或聊天历史适合先测空间收益与低频查询成本。若已有向量能放进磁盘，且在线延迟要求较高，重算未必划算。recompute_embeddings=False 可以关闭重算，改回存储向量的方式。

先用自己的数据测一次，再决定省下的空间是否值得。
