munder-difflin：把终端 agent 编成一间办公室

2026-08-19 ·笔记 ·5733 字 ·约 14 分钟 ·阅读 次
AgentElectron架构

munder-difflin 是个 Electron 桌面应用，把你已经在终端里跑的那些 agent CLI——claude、codex、grok、opencode 等十种——包成一间 2D 办公室：每个会话是一个走来走去的像素小人，互相发消息时有信封在桌子之间飞。
名字是《办公室》里那家最差的纸业公司，主管叫 Michael，他是这层楼的老板，你是他的老板。
听起来像个玩具。但它代码里最花心思的地方不是那间办公室，是**「谁有权往一个真实终端的输入行里打字」**——这个问题它想得比我见过的任何 agent 编排工具都细。

先说规模

到 2026-08-19 的 HEAD（92461ab），仓库从 5 月 31 日起攒了 710 次提交，src/ 下 185 个 ts/tsx 文件、53,166 行。两个主要文件都偏大：index.ts 4,582 行，hive.ts 2,464 行。38 个测试文件，跑在 node 自带的 node --test 上。

版本 0.4.4，README 自称 working prototype。这个自我定位是准的：功能面铺得很宽（语音编排、Slack 接入、内置 Monaco IDE、技能目录、看板、成本账本、断路器、自动更新），有些地方深得出乎意料，有些地方文档已经和代码分叉了——后面会讲。

两个数据平面

这是它唯一真正的架构决策，别的都是推论。

SPEC.md 里写得很直白：钩子给不了你用户想看的原始字节流，而光有终端输出流又没法可靠知道当前在跑哪个工具（除非去解析输出，很脆）。所以两条路都要：

  • 终端平面——主进程用 node-pty 把每个 agent 拉起成真进程，输出按 id 走 IPC（pty:data:<id>）推给渲染进程，xterm.js 渲染。逐字节真实，你能直接往里打字。
  • 事件平面——每个 agent 启动时用 --settings 把钩子指向一个自带的小 shim，shim 把生命周期负载写进主进程监听的本地 socket（POSIX 上是 hive 目录里的 hooks.sock，Windows 上换成按 hive 路径 sha1 命名的具名管道）。PreToolUse/PostToolUse 决定小人走去哪个工位，Notification 决定它是不是在挥手叫你。

画布是事件驱动的，终端视图是原始字节的，两者不共享判断。这个切分很干净，也是它敢让小人动起来而不撒谎的原因——动画的每一帧背后是一个真实的钩子事件，不是猜的。

顺带一个有意思的历史：SPEC.md 通篇还在讲用 tmux 附着到你已有的窗格（tmux pipe-pane 读、send-keys 写），明确写着「不 spawn、不拥有 claude 进程」。而实际发布的东西自己 spawn PTY、自己拥有生命周期。那份 spec 现在是考古材料，不是文档。

蜂巢：协调层就是一个 git 仓库

多 agent 部分叫 hive，落在 <harnessHome>/hive/，是个本地 git 仓库。核心是四条锁死的规则，每一条都能看出是被具体的坑教出来的：

只有主进程提交。 十几个进程并发 git commit，撞的是 .git/index.lock，仓库会坏。所以 agent 一律不碰 git，只写普通文件。提交逻辑重试 5 次，退避 50 * (attempt + 1) 毫秒，并且把 mtime 超过 10 秒的 index.lock 当残锁直接删掉。

每个文件只有一个写者。 agent 只写自己的 agents/<id>/ 目录。跨 agent 的投递由主进程的路由器完成：把发信人 outbox/ 里的消息搬进收信人 inbox/。一条消息一个 JSON 文件，写临时文件再 rename——不是往一个共享的邮箱文件里追加，那种在 git 下必然冲突。

append-only 的 log.jsonl，消费者各自记游标。唯一真正被多方编辑的是 board.md，办法是让 GOD agent 当唯一的抄写员。

消息 schema 是 FIPA-lite。 它只借了 FIPA-ACL 里唯一有用的概念——言语行为（request/inform/propose/query/agree/refuse/done），把 LISP 语法丢了。防活锁靠三条：只有 request/query/propose 有义务被回复（inform/done 是终止的）；每次回复 hops 加一，超过 HOP_CAP = 12 路由器直接丢弃并记一行 drop；重复见到已处理的 id 是幂等 no-op（靠 cursor.json）。

最后一米：谁有权往终端里打字

docs/message-queue.md 是整个仓库里我最推荐读的一篇，一千多字讲一件很窄的事：一个真实 CLI 只有一根输入行，而想用它的不止你一个。

它先把两个都叫「队列」的东西分开：harness 自己的 MD 队列（zustand 里，每个 agent 一条，存着被暂存的自动消息），和 Claude Code 内部的队列（它已接受但没开始做的文本）。harness 看不见后者，也从不对它做推理。这个区分很重要，因为混淆它们会让人写出「我以为它闲着」的代码。

然后是一个门。所有想碰到运行中 agent 的路径——composer、Slack 入口、inbox 提醒、定时 /compact——统统 enqueueMessage，由一个 drain 循环决定何时放行。文档里写明这条是载重的：

当 inbox 提醒直接往终端写时，它就是第二个写者，有它自己关于「输入行何时空闲」的判断——于是它的文本落在了用户写了一半的那行上面，提醒和用户的句子被当成一个乱七八糟的 prompt 一起提交了。

放行要五个条件同时成立：agent 状态是 idle、没有全局暂停（或这条消息被手动放行）、过了 35 秒开机宽限、isTerminalAutomationSafe(ptyId) 通过、距上次投递超过 4.5 秒。而且只有两次 PTY 写入（文本、回车）都成功才算送达，失败就留在队列里重试。

isTerminalAutomationSafe 才是精华。它在四种情况下拒绝投递：PTY 已退出、你打开了一个菜单（picker）、你有未提交的草稿（draft）、刚放开输入行的短暂重绘窗口（settling）。picker 和 draft 都是推断出来的而不是被上报的，所以 30 分钟后过期——不然一个没被观测到的菜单关闭就能把这个 agent 的队列卡到会话结束。

然后是两条我很喜欢的硬规矩：

自动化永不擦掉你的文字。 过期意味着排队的消息被打在你那行后面，两者融成一个 prompt。早先的版本会先发 Ctrl-U，那悄悄销毁过真实的草稿——它们只是被放置了一分钟而已。

自动化永不关掉你的菜单。 我们不会往 picker 发 Escape。你可能是故意打开它然后走开的；为了给一条排队消息腾地方而把它收掉，不是 harness 该做的决定。

最漂亮的一段是第 4 节。inputDirty 靠数 term.onData 的按键推断，会漂移——一个自己吃掉按键的 TUI 会让计数停在零以上，而屏幕上其实是空的，这叫幽灵草稿，它会挡住一条本该发出去的消息。修法是直接读 xterm 已经渲染好的屏幕缓冲（term.buffer.active 里光标那一行，剥掉提示符装饰）。关键在于这个读取是单向的：

  • 屏幕说空 ⇒ 相信它，撤掉阻塞
  • 屏幕说有字、或者读不出来 ⇒ 退回按键计数

理由是两种错误的代价不对称：误判「空」会开门并把消息糊到你正在写的句子上；误判「有字」只是让那条消息多等一会。所以让便宜的那种错发生。还有一个更细的：inputDirty 在你按下键那一刻就置位，但字符要等 PTY 回显才进 xterm 的缓冲——这个间隙里读缓冲会得到「空」，正好是贵的那个方向。所以距上次按键 1 秒内的读取返回「不知道」，什么都不清除。

我读完这节的感受是：这种「先想清楚两种错误哪个更贵，再决定让判断往哪边偏」的写法，在 agent 工具里太少见了。大部分项目在这个位置会写一个 if (isIdle) sendKeys(...) 然后收 issue。

那个系统提示词前缀不许含变量

hive.ts 里 injectedPrompt() 上面有一段大写的注释，标着 🔒 PROMPT-CACHE INVARIANT：

保持这个前缀无易变量。它只插值那些在一个 agent 整个生命周期里稳定的值（名字、id、目录、根、semanticMemory）。不要在这里加日期、UUID、计数器、board/registry 状态，或任何 Date.now() 派生的文本：一个每次 spawn 都变的前缀会打掉 Anthropic 的 prompt cache（每一轮都要重新预热整个系统提示词）。

易变的上下文走活的通道——inbox 和 PTY——绝不烤进前缀。这是个很实际的成本约束被写成了不变量，而且写在了最容易被人无意破坏的那个函数头上。

紧跟着还有一段 🪟 NO SHELL SYNTAX，同样值得抄：注入给 agent 的每条路径和命令，都必须是它在自己那个平台上真会敲的样子。两个曾经悄悄只在 Windows 上坏掉的习惯被点名——$VAR 在 cmd.exe 下展开成空，所以那些指令在每一台 Windows 上都是死的；用字符串拼 '…' + '/inbox/' 会告诉 Windows agent 去读 C:\Users\x\hive\agents\god/inbox/。修法是烤进 join() 出来的绝对路径：跨平台、不需要展开、而且仍然对 prompt cache 稳定。

Windows 上的沉默

v0.4.4 的发布说明标题是「Windows 上的 agent 终于能互相说话了」。根因在 pty.ts 里写了一大段，是我这两天读到最好的一个 bug 故事。

Windows 上 .cmd/.bat 不能直接交给 CreateProcess，所以 spawn 走 cmd.exe /d /s /c "<line>"。这意味着 argv 变成一个由 cmd.exe 解析的单字符串，而 cmd.exe：把 CR/LF 当语句分隔符——在考虑引号之前——所以多行参数会被截断在第一个换行，剩下的当命令执行；把 (/) 读成块分隔符；没有反斜杠转义；命令行上限约 8191 字符。

而注入的那段 hive 协议提示词是 6.1k 字符、11 行、62 个括号。

结果：每一个用 npm 装的 CLI（OpenCode 永远如此；claude.cmd 在没有原生 claude.exe 时也是），启动起来看着完全健康、界面正常，但从来没收到过 HIVE PROTOCOL 那一段，从来不知道 inbox/、outbox/ 存在，于是没有任何一个 agent 听到过另一个 agent 说话。Claude 看起来能用，只是因为它的原生 claude.exe 绕过了 cmd.exe。

修法是把 npm 的 .cmd shim 解码回它真正要跑的「解释器 + 脚本」，然后用参数数组去 spawn——这样 node-pty 自己那套符合 MSDN/CRT 规则的 argsToCommandLine 生效，直接交给 CreateProcess，中间没有 shell 解析器。引号里的换行在那儿只是一个普通字符，上限也从 cmd 的 8191 变成 CreateProcess 的 32767。

parseNpmCmdShim 是纯函数（只吃 shim 路径和内容，不碰文件系统、不看 process.platform），所以能在 macOS/Linux 上单测——Windows 构建通常就是在那儿写的。它模式匹配了 npm cmd-shim 历史上三代产物的形状，并且任何看不懂的形状都返回 null 退回 cmd.exe 路径，保证不比原来更差。

然后是第二次修（14cb1e4）。opencode-ai 的 bin 指向 ./bin/opencode.exe——一个编译好的二进制，不是 JS 脚本——npm 于是写出一个没有解释器的 shim：

解析器只建模了「两个 token」那种形状。这里只有一个带引号的 token、前面什么都没有，于是 before 是空、word 是 undefined，返回 null，笔直掉回那条会截断的 cmd.exe 路径。每一台 Windows 上的 OpenCode 安装都确定性地中招。提交信息里那句最狠：

agent 启动了、渲染了、看起来很健康，而且完全不知道自己有一个收件箱。

还有一句是这个 bug 能活过一次发布的真正原因：cmd.exe 回退路径是静默的。 现在它会警告，并且报出它没能解码的目标，以及这次 spawn 里是否真有多行参数处在风险中。这个改动比修解析器本身更有价值。

GOD agent：机制与智能分开

Michael 是个普通的 claude 进程，坐在 desk-ceo，标记 isGod。设计文档把分工讲得很清楚：GOD agent 是智能，主进程是机制（git、socket、路由）。

它的职责是名册与路由（registry.json）、裁决（读每一条对外请求，例行的自己解决，只有关键的才升级）、当 board.md 的唯一抄写员、维护任务台账（tasks.json）。什么算「关键」（破坏性操作、花真钱、范围变更、无法解决的冲突）写在它的系统提示词里，而不是代码里——文档明说这是主要的控制面：要调的是提示词，不是代码。

这个选择有代价，它也承认了：没有独立的审批队列，人类介入靠的是每个 agent 自己 Claude Code 会话里的工具权限提示（可以从手机上通过 /remote-control 远程批）。也就是说，安全边界的可靠性等于那段提示词的可靠性加上权限提示的覆盖度。对一个 5–15 个 agent 的个人 floor 也许够；再往上我会不放心。

还有个很实际的细节：钩子服务器会在 SessionStart 和每次 UserPromptSubmit 时，把当前名册作为 additionalContext 塞给 GOD——注释说得很清楚，fleet.json 在磁盘上永远是新的，但 GOD 的上下文不是：重启后它接上一份描述旧楼层的 transcript，然后去给早就不在的 agent 发消息。这是个只有真跑过才会碰到的问题。

记忆：markdown 优先，索引可缺

记忆分两层，主从关系很明确。

底座是每个 agent 的 memory.md 加共享 board.md，纯 markdown。文档里直接否掉了重型向量层（Letta/Mem0/Zep），理由是两条：5–15 个 agent 的规模上不需要；更重要的是架构上不对——那些东西想拥有 agent 运行时，而这里的运行时是 CLI 本身。这个判断我认同。

语义层是 memory.ts 包的 MemPalace CLI，走 CLI 不走 MCP，整个 hive 共用一个 palace，把每个 agent 的 memory.md 挖进它自己的 wing（按 mtime 判断要不要重挖）。关键是检测并降级：mempalace 没装就整体 no-op，markdown 记忆照常工作。顺手一个细节——mempalace mine 尊重 .gitignore，所以它往每个 agent 目录扔一份 .gitignore 排掉 settings.json/cursor.json/inbox//outbox/，而不是去改 mine 命令。理由是那个钩子配置是个大 JSON blob，会把 wake-up 摘要冲掉。

reflect.ts 补的是压缩那一半。它自称「清洁工缺掉的 CONDENSE 半边」：清洁工会标记超大的 memory.md（"Needs condensing."）但从不真的缩小它。压缩把文件重写成有界的三段——钉住的持久事实（永不动）、一份滚动的递归摘要、最新的 K 段原文——用便宜的无头 claude -p（claude-haiku-4-5）去总结被驱逐的尾巴。预算 128 KB。

安全性是分层的，注释说得很明确：先备份（无损冷拷贝）→ 不信任就验证 → 原子替换。任何一步检查失败，原文件逐字节不动，唯一的副作用是一行 condense-abort 日志。还有一条解释了为什么这个循环必须在 Electron 主进程里而不是 launchd：macOS 的 TCC 会拦住 launchd 拉起的 shell 访问 ~/Documents，只有这个进程拿到了文件夹授权。

刹车与账本

breaker.ts 的开场就说清了动机：Claude Code 有 --max-turns，但没有美元上限，所以自己造一个。

这个模块只管策略——触发条件加 steer → constrain → stop 的升级阶梯——没有副作用：读信号、返回决定，执行由 index.ts 里的心跳去做。输入聚合三路：用量采样（成本与 token 速率）、钩子事件（重复的同名同参 PostToolUse 是跑飞的典型信号、api_error 风暴）、文件 mtime 无进展。速率用的是连续累计采样的差分（Δoutput/Δt），不是把单次采样当增量——这是个很容易写错的地方。

默认值透露了它的性格：hardStop 默认关，没开的话阶梯顶到 constrained 就不会杀进程；一个 beat 只升一级，绝不跳到 kill；健康的 beat 会降一级（可恢复）；token 速率兜底定在 60,000 output tokens/min，注释自称「故意定得很高的粗糙兜底」；无进展要连续 2 个 beat 才算（一次 inbox ack 或 statusline 突发不该单独触发）。还有一个上下文压缩豁免：PreCompact 打开它，让压缩带来的 token 爆发不触发 Δoutput 那几个臂，PostCompact 或任何 SessionStart 关掉它并留 90 秒尾巴。

成本那边，transcript.ts 直接读 ~/.claude/projects/ 下的 JSONL transcript 拿真实 token，不是估的。里面有个很典型的兼容坑：Claude Code 的 project key 是把 cwd 里每个非字母数字字符换成短横（/Users/me/app → -Users-me-app），而 2026 年之前的 POSIX 写法是丢掉前导斜杠、只换斜杠，于是点号活了下来。它把两种 key 都留着，只为了让改动之前写的 transcript 还能读。

顺带一个我觉得写得最好的注释在 hive.ts：cost-ledger.jsonl 是 append-only 的，每次用量采样加一行，而 hive 一直在提交——一个跟踪它的仓库会在每次提交里存一份整个文件的新拷贝。它算得很具体：一个四分之一 GB 的账本加几千次提交，就是几百 GB 的 blob 要 git 去走，这就是一次例行 gc 变成多 GB pack-objects 的原因。而且它点出了那个真正的陷阱：git 对已经在索引里的文件会继续记录，不管 .gitignore 说什么——所以只加 ignore 行读起来像修好了，仓库照旧在长。所以它专门做了一次 rm --cached，而且在动手之前先探测有没有真的被跟踪，免得每次启动都在重试路径里重写索引。

文档已经和代码分叉了

这是我要给的最实在的批评，而且我是查过的。

HIVE.md 把「自治循环 = Stop 钩子」列为锁死的设计决策之一，Phase 1 标着 ✅：agent 干完一轮，Stop 钩子返回 {"decision":"block","reason":…} 让它接着干，靠 stop_hook_active 防死循环。

代码里已经没有这回事了。hooks.ts 的 Stop 分支现在直接返回 {}，注释写着：

永远不要把未读的 hive 邮件在 Stop 处变成一次强制续跑。那条老路绕过了终端草稿/HITL 安全，并且可能在用户正在回答一个问题的时候花掉额度。

改成了 inbox 文件保持在磁盘上，由渲染进程那条「只在 idle 时投递」的受控路径稍后唤醒——就是上面那五个条件的门。这个改动是对的，而且理由比原设计更成熟：原设计里 Stop 钩子这条自治通道，恰好绕过了它自己后来花最多心思建的那道门。

但 HIVE.md 一个字没改。而且 drainForStop() 这个函数还在 hive.ts:1029，我全仓库搜过，生产路径上没有任何调用者，只有两处注释提到它，和一个测试文件在调它。也就是说：设计文档的招牌机制，现在是一个孤儿函数加一份还在宣称它是 ✅ 的文档。

SPEC.md 的情况更彻底，前面说过，整篇讲的还是 tmux。

我不觉得这是懒。710 次提交、两个半月，从 tmux 附着改成自己 spawn PTY、从 Stop 钩子强制续跑改成受控队列投递，这是两次正确的方向转弯。问题只在于文档没跟着转，而它们又都自称是 source of truth。读这个仓库的正确顺序是：docs/message-queue.md 和代码注释可信（我抽查了 FLUSH_COOLDOWN_MS = 4500、STALE_INPUT_MS = 1_800_000、BOOT_GRACE_MS = 35_000、ECHO_GRACE_MS = 1000，与文档逐一对得上），HIVE.md 当路线图读，SPEC.md 当考古读。

另外两件该知道的事。一是许可证有个真陷阱：代码是 MIT，但捆进来的像素美术（tileset、地图、《办公室》全体角色的底图）来自 LimeZu 的 FREE VERSION 授权，仅限非商业使用，重上色的精灵图继承这个限制。要商用必须换掉资源或买授权，README 把这条写在了 IMPORTANT 框里，算是坦诚。二是 blog/ 目录下有 130 篇文章，标题是 claude-squad-vs-munder-difflin、best-ai-coding-agents、generative-engine-optimization-techniques 这类——一个相当直白的 GEO/SEO 内容矩阵，每篇还配了手绘风格的 hero 图。这跟工程质量无关，但看仓库时值得知道自己在看什么。

我会借走什么

抛开那间办公室，有四件事我认为是可以直接搬的：

一、文件系统当协调层，单提交者。 想让多个 agent 协作又不想引入消息队列，「每个 agent 只写自己目录 + 一个进程负责搬运和提交」是成本极低的一套。原子 rename 投递、per-agent 游标幂等、hop cap 防乒乓，三样加起来不到两百行。

二、把「谁能碰共享的窄资源」写成一份单独的文档。 那根输入行只是个例子。任何有人和自动化同时要用的资源——一个 tty、一个分支、一个 API 配额——都值得一份「一个门 + 放行条件表 + 两种错误的代价对比」的文档。

三、判断按代价不对称来偏。 这是上一条的方法论内核。不要问「怎么判断得更准」，先问「判错的两个方向哪个更贵」，然后把不确定性全推给便宜的那一侧。munder-difflin 的读屏只能清除草稿不能发明草稿、回显间隙内返回「不知道」，都是这一条的直接应用。

四、把成本约束写成带 🔒 的不变量，压在最容易被破坏的函数头上。 prompt cache 那条注释的价值不在于它解释了 prompt cache，而在于它出现在唯一一个「顺手加个时间戳」就能悄悄让每轮成本翻倍的地方。

至于那些走来走去的小人——它自己的 spec 里写了一句很清醒的话，说这个隐喻的真实风险是落成噱头，缓解办法是让每个动画都真的告诉你一件你原本不知道的事；如果走到书架前没能比一个文字标签更快地传达「它在读文件」，那就是造了个玩具。这个自我要求，比大部分同类项目的 README 都诚实。
