keepane，给 agent 用的终端工作空间

2026-09-28 ·笔记 ·10160 字 ·约 25 分钟 ·阅读 次
Rust终端AgentMCP

终端多路复用器是给坐在键盘前的人写的，分屏、切窗口、断线重连，前提都是有个人看着。现在 pane 里跑的常常是 agent，人不在跟前，要的东西就变了。
keepane 是按后面这个前提写的。每个 pane 有名字、有收件箱、有工作模式，pane 之间能互发消息，也能让对方直接执行一条命令；几个 agent 要商量同一件事的时候，还能拉一个频道说话。同一台机器上如此，配过对的两台电脑之间也一样。
终端断了 pane 里的程序照跑，跑完了、或者它反过来等你拍板，手机、飞书或者 webhook 都会告诉你。agent 用了多少 token、花了多少钱，这一轮读了什么改了什么、哪条命令跑挂了，也都摆在面上。tmux 的键、命令和配置在这里照用。

起因

一开始是想找个现成的用，找了一圈没有合预期的。能用的那些都还是按「有人看着」写的，pane 里跑的是什么它不关心，更不会让两个 pane 说上话。于是自己写，第一个提交的标题是「wmux: tmux-style terminal multiplexer for Windows」，那会儿还叫 wmux。
真用起来才发现分屏解决的只是摆放。几个窗口里各跑一个 agent，想让它们配合起来，眼下就两条路。一条是用各家 agent 自己的协议，一家一套，谁也不认谁，换个工具就得重接一遍。另一条是用 agent 内部那套派子任务，它跑在一轮之内，不占 pane、看不见、也接管不了，断了就断了。
那就往下挪一层。不管跑的是哪家 agent，还是一个普通 shell、一个脚本，它都坐在一个 pane 里，pane 是大家都有的那层东西。通信放在这一层，给每个 pane 一个名字和一个收件箱，里面跑的是谁就不重要了。
pane 于是从一块屏幕变成了一个有地址的执行单元。改名也是这时候的事，wmux 这名字 GitHub、winget、crates.io 上都有人在用了，0.14.0 起改叫 keepane，keep 加 pane，终端没了 pane 里的程序还在。
keepane 不管模型怎么想、agent 怎么分工，只管执行环境、消息和状态，所以不绑任何一家的 agent。

消息

给 pane 起个名字，它就能收消息：

-w 是等送达，trace-message 是等做完，回来的是输出和成败。另一种等法不盯消息盯屏幕：wait-output -t %server "Listening on" 堵在那里，直到那个 pane 打出含这段字的一行，把这行给你。

发送方能填的只有 --to、--re、--task 三样，其余由服务端盖章：

from、name、mode、id、hop、via 都不许发送方给，给了报错。来源能伪造的话 hop 上限就拦不住循环，两个 agent 能一直对着回信，现在超过 8 跳拒收。
字段顺序固定、中间不留空格，同一条消息每次生成的字节完全一样，写测试和给程序解析都省事；值里不会出现空格和 ]，按空格切开就读回来了。这行原本是 JSON，用了一阵实在看不下去，0.17 改成字段式，JSON 只留在事件日志里。

工作模式

投递时机由收件方决定，一共三种：

normal：不自动投递，程序自己用 read-message 取，窗口标记上显示 @
shell：keepane 的提示符钩子看到 shell 回到提示符，就把命令打进去回车
ai：agent 的轮次结束 hook 调过 pane-ready，或者它的会话记录显示这一轮结束了，就把正文当提示词粘进去，回车单独发

投给 shell 的那条，信封写成不执行任何东西的形式放在命令前面，PowerShell 里是行内注释 <# keepane #12 from %lead #> cargo test，bash 和 zsh 里是 : 的参数。这样来源同时留在屏幕、shell 自己的历史和 keepane 的历史日志三处。
投给 agent 的那条分两步：先粘贴，再单独发回车，最早在粘贴后 300 毫秒、并且 150 毫秒内没有新输出才发，最晚 2 秒。因为 agent 的输入框可能吞掉紧跟在粘贴后面的回车，Codex 就会这样。回车后 2.5 秒还是一点输出都没有，就再发一次。这期间有人在 pane 里打字，回车就留给这个人。
消息按发送当时对方的模式投递，不按现在的。写给 agent 的一段文字，不会因为这个 pane 中途被切成 shell 就被当命令执行。
pane 此刻是什么状态用一个词说清楚，#{pane_state} 能取到，dashboard 和手机页上也写着：idle 空闲，busy 在干活，typing 有人按过键但还没回车（消息就等着，不往人正在写的那行里插），no-agent 是 ai 模式的 pane 回到了 shell 提示符、agent 已经退出，unknown 是 shell 模式的 pane 从没发出过提示符标记（比如 cmd），exited 是程序退了。

群聊

一条消息只进一个收件箱。三四个 agent 做同一件事的时候，这样传话很快就乱：谁知道哪一句、谁该接着说，全靠派活的那个 pane 自己记。0.73 加了频道，每个 agent 用一个称呼和角色加进去，说自己要说的，想看的时候自己读。

上面这张是真实的频道，不是摆拍：这次给 UnifyTerm 做「在 keepane 的 pane 里也能用它的命令」那件事，两个项目的 agent 就在这里商量，中间我插了两句问版本。

要紧的是默认不推送。说的话留在频道里，不进任何人的收件箱，所以五个 agent 的频道不会每句都塞进另外四个的上下文里，token 不会成倍烧，也不会出现它们收到就想回、互相回个没完。被 @称呼 点到的那个另说：它立刻收到一条收件箱消息，写明频道和谁说的，下面附上它上次读完之后别人说的话，最多二十句。只推一句的话，它不知道前面在讨论什么。想听全部的成员，加入时写 --hear all，两秒内的几句合成一条送过去。
身份是服务端盖的。pane 只能以自己的身份加入和发言，自己能选的只有称呼和角色；机器、session:窗口.pane、pane 编号和名字、agent 种类、模型这些记在成员上，也记在它说的每一句上。你在所有 pane 之外说话，身份是 you@<机器名>，不用加入。shell 模式的 pane 收不到点名，那边收到什么都会当命令执行，发言者会收到说明。每个成员每分钟最多二十句。
成员比 pane 活得久。pane 关掉或者服务重启之后，成员还在频道里，只是变成离线，频道里写一句；同名的 pane 回来（恢复会话会恢复 pane 名），或者有 pane 用它的称呼加入，它就重新在线，接着从原来读到的地方读。自己走的、或者被你移出去的，标成「已离开」，不算成员数，@ 它会回一句没送到。离线或离开超过 chat-days 天的自动清掉。
频道有一个永不改变的 UUID，还有名字、topic 和 tags，存在事件日志旁边，一天一个 jsonl 文件，默认留 30 天。同样这六件事也是 MCP 工具，所以 agent 用工具调用就能加入和发言。有人在频道里 @you 叫你，keepane 像 agent 干完活那样通知你，桌面通知的按钮直接跳到那个成员的 pane。
别的机器的 pane 加入频道还没做，排在后面的版本里。

看板

C-b v 弹出来，或者在任何终端里跑 keepane dashboard，像 lazygit 那样分面板。一共三页，< > 翻。

第一页是干活的那页。左边 [1] 所有 pane 按 session 分组，列出工作模式、忙闲、收件箱排了几条、安静了多久、在跑什么程序，跑 agent 的写它的花费和上下文，标题里是总花费；[2] 是选中 pane 的收件箱，[3] 是任务。右边 [4] 跟着光标走：停在 pane 上就是这个 pane 的地址、目录、pid、跑了多久、它自己报的状态，下面可以切它此刻的屏幕、回滚、事件、agent 的 trace，或者它所在仓库的 Git 情况；停在某条消息或任务上，右边立刻排好版显示那一条，谁发给谁、每一步的时间、正文和执行输出。
窗口宽过 150 列，最左边多一栏：上面 [0] 是选中 pane 的目录，像 mini.files 那样走，h 回上级、l 进目录，光标停在文件上右边就显示它的文本（最多前 256 KiB）。下面每秒写这台机器的 CPU、内存、交换区、磁盘和网络、温度、功率、电池。条目前面按类型标 emoji，终端用 Nerd Font 的话 set -g dashboard-icons nerd 换成图标。
第二页是群聊，第三页是这台机器分享出去的东西：每个分享标着还有多久过期、被下载过几次，右边是链接、谁打开过和一个二维码，在 [0] 里对着文件按 S 就能分享它。
看板不只是看。对 pane 可以 s 发消息、r 改名、m 改模式、R 解卡、o 跳过去、x 关掉；对收件箱可以删（u 撤销）、上下移、置顶。关 pane、删消息、把 pane 切成 shell 这三样会先问一句。按 L 在底栏列出配过对的机器，每台后面写着它在本机有什么权限，能连接、断开、收回或者解除配对。

用量与花费

keepane 认得 pane 里跑的 agent：Claude Code、Codex、pi 和 Cursor CLI。这几个都会为工作目录写一份会话记录，keepane 每 2 秒读一次新写的部分，从中取模型、token、调用工具和回复的次数、上下文占了多少；CPU 和内存从进程表读。Cursor 的对话 keepane 读不了，所以它只有 CPU、内存和 hook 报的模型。
花费这个数的口径要说清楚：pi 自己记了花费就直接用，其余的按 LiteLLM 那份公开价目表给每个模型的新输入、读缓存、写缓存、输出分别计价。表上是各家 API 的标价，而你很可能在用 Claude Max 或者 ChatGPT Pro 的订阅，所以这个数的意思是「同样的活走 API 要花多少」。表里没有的模型不计价，数字后面带个 + 表示至少这么多。set -g agent-cost off 就不下载也不显示。
Codex 的数字按它自己的算法来：上下文占比扣掉任何会话开头都有的 12000 个 token，和它状态栏显示的一致；它的服务商给了套餐限额的话，5 小时窗口和每周窗口各用了多少也一并读出来，agent_limit 能放进状态栏。
看的地方有四个：看板的 pane 列表、手机上 agent 卡片多出的那一行、keepane list-agents -J 给脚本，以及 agent_model、agent_cost、agent_context 这些格式变量，可以写进 pane 边框。

一步步在做什么

同一份会话记录里，连每一步的起止时间都有。看板右边按 T 切到 Trace，把选中 pane 的 agent 画成瀑布图，每 2 秒重画一次：

每种步骤一种颜色：模型品红，读取和搜索青色，改文件黄色，跑命令蓝色，子 agent 绿色，联网和浏览器亮青和亮蓝，skill 和记忆亮品红和亮黄，hook 暗色。失败的红色并标 ✗，记录里说了原因就写上，被你拒绝的写 denied，被 hook 拦下的写 hook: …；还在跑的加粗，末尾有 ▶。
最上面两行是后来加的，用起来最省事：agent 在等你做什么（等权限、等你回答），以及还在后台跑着的任务，直到任务自己说完了、被停掉或者 agent 重启。同一种已结束的步骤连着三步以上会折成一行，显示最后一步，后面写 +N 是一步接一步，×N 是同时发出的，不然整屏都是读文件。
每一轮用你的提问命名；不是你提问开始的那一轮，就用开始它的东西命名：后台任务完成、! 命令、定时任务、别的会话发来的消息。Claude 的子 agent 排在启动它的那次调用下面。默认只展开最新一轮，e 全部展开。
会话记录是一件事做完才落一行，所以模型调用要等回复写完才出现；一轮还在跑、又没有工具在跑的时候，就是模型从上一步起一直在工作，显示成 thinking。给脚本的是 keepane trace-pane -t <pane>，-J 出 JSON。

完成就通知

人走开了，总得有个东西把「跑完了」送到眼前。keepane 认六种完成：一条跑了一会儿的命令结束、agent 这一轮结束、agent 反过来在等你、一条消息的任务走完、程序退出、没有 agent 的 pane 响了铃。

手机页开着的时候顶部弹横幅，点一下跳过去，响一声，安卓还震一下，标签页标题上记未读数；页面在后台时完成的，切回来补告诉你
set -g notify on 走系统桌面通知
set -g done-webhook <地址> 往外发一条，done-webhook-format 选格式：飞书、企业微信、钉钉、Slack、Discord，或者 text（ntfy、Bark 这类只要一行字的）；飞书、钉钉的机器人开了签名校验的，把密钥写进 done-webhook-secret
想接别的服务就挂 pane-done hook，这次完成的信息都在环境变量里：KEEPANE_DONE_KIND、KEEPANE_DONE_TEXT、KEEPANE_DONE_OUTPUT、KEEPANE_DONE_OK、KEEPANE_DONE_SECONDS，还有一份 KEEPANE_DONE_JSON

「等你」那种走 setup 装的第二个 hook：agent 要权限、或者问了你一句话就跑 keepane pane-wait，通知写成 waits for you: Claude needs your permission，底下把问题和那几个选项一并捎上，所以在手机上扫一眼就知道该回哪个。Claude Code 要等问题挂了六秒左右没人理才触发，免得你本来就坐在跟前。Codex 和 Cursor 问你问题的时候会话记录里一个字都不写，这两家改成读屏幕上的那几行关键字。
agent 那一轮的通知里还带一段它在仓库里干了什么。起点取这轮开始时仓库所在的提交，结束时比一次：

这段同时出现在 trace-message 里，所以派活的那个 pane 用 -w 等结果时会一起拿到，不用再去问「你到底改了什么」。它统计的是工作区在这段时间里的全部改动，不分是谁改的，所以两个 agent 共用一个工作区就会混在一起，要分清得给每个 agent 一个 git worktree。git 只在有人要看的时候跑，每次最多 10 秒，而且不抢 agent 正在用的 index 锁。
哪些算完成、对哪些 pane 生效，都能调：done-events 挑事件，done-after 30 要求命令至少跑够 30 秒，done-panes named 只管起过名字或者 ai/shell 模式的，done-lines 5 顺带把 pane 最后几行输出捎上。同一个 pane 三秒内只响一次；keepane list-done 翻最近一百条。
手机页那条有个物理限制得讲明白：普通 HTTP 的页面发不了系统通知，锁屏或者切走之后浏览器会把页面暂停。所以锁着屏也要收到的，得走 hook、webhook 或者下面的飞书。

飞书

通知推出去只是单向的，想回一句还得找台电脑。所以接了飞书：用你自己建的企业自建应用（Lark 也行），通知由应用私聊发给你，你在聊天框里直接回。长连接是 keepane 主动连向飞书的，这台电脑不开任何对外端口，也不需要公网地址。

回「在等你」那种通知：回复立刻送进 pane。单个键按原样按下，1、2、y、n、esc、enter、up、down、tab；其他文字先打进去再回车
回别的通知：当成一条消息发给那个 pane，和 send-message 一样排队，agent 用 send-message -r 回答时，回答会回到飞书的聊天里
命令：/panes 列出 pane 和哪些在等你，/to <pane> <文字> 发消息，/key <pane> <按键> 立刻按键，/screen <pane> 看屏幕

只认你放进白名单的人，只收和机器人的单聊。默认能碰的很有限：按键只发给 agent，消息只发给 agent 和 normal 模式的 pane。没有 agent 的 pane 收到按键、shell 模式的 pane 收到消息，都等于执行命令，所以要单独 --shell 授权；/screen 会把屏幕内容传到飞书的服务器上，要 --screen。这台电脑上属于别的机器的 pane 更要单独的 --remote，因为那台机器信任的是你，不是你放进机器人的每个人。授权只能在 pane 外面做，agent 开不了这些口子。

手机

keepane web 在终端里打一个二维码，手机扫了是一个列出所有 pane 的页面，按 session 和窗口分组，标着每个跑的什么程序、有没有提醒标记。点进去看屏幕、带颜色，屏幕一变就推过来，不用刷新。

卡片上那行大字是 pane 的名字，没起名就退到程序自己设的终端标题，再没有才显示程序名；下面一行是在跑什么、最后输出的一行、多久没动静，还有一个小圆点表示空闲还是忙、收件箱里排着几条。不点进去就知道哪个跑完了。列表顶上能换成网格，一格一个 pane，带上它最后四行输出，手机竖屏一行两格。
底下输入框是边打边发的：你在框里打字那边就跟着出，删字那边也跟着删，输入法选好字才发，回车就是回车。嫌它太激进，视图菜单里可以改成等回车再发，每台设备各自记住。上面一排是手机键盘没有的键，Ctrl+C 和回车钉在最右边不会被滚走；先点 Ctrl、Alt 或 Shift（可以几个一起按住）再点别的键，就是带着修饰键按下。
shell 和 ai 模式的 pane，输入框旁边有个信封按钮，按下去发的就是消息了，进这个 pane 的收件箱排队，跟 send-message 同一条路。长按卡片或者点「排队 N 条」能把收件箱打开：正在处理的那条、排队每条的全文，可以置顶、上移、删掉，删了还能撤销。
顶栏的对话气泡按钮打开群聊，和看板第二页是同一批数据：

旁边的回形针是 0.66 加的，把手机上的文件传进这个 pane 的文件夹，默认落在它当前目录下的 keepane-uploads，里面放一个内容为 * 的 .gitignore，所以 git status 不会因此多出一堆东西。同名文件不覆盖，新的存成 report (1).pdf。每收到一个，电脑上的状态栏说一声，并写明来自哪个地址。
手机屏幕行太少，vim、htop、agent 这些占满屏的程序摊开就没法看。视图菜单里的「适配这块屏幕」让当前 pane 占满所在窗口，整个会话调成手机的行列数，这些程序按手机的大小重画一遍。一个会话只有一个大小，所以适配的这段时间，电脑跟前和别的手机上看这个会话也是小的，页面和状态栏都会说一声。离开这个 pane、退回列表、锁屏都会恢复，没人看了 10 秒 keepane 自己也会恢复。
页面在 0.25 整个用 React 和 HeroUI 重做了一遍，打包成一个文件编进二进制，所以电脑浏览器里也是同一个页面：宽屏时左边列表右边 pane，列表能收成一条窄栏。右上角那个菜单管页面外观、终端主题（选了电脑上的终端跟着变）和页面语言，旁边实时显示到电脑的往返时间，100 ms 以下绿点，300 ms 以下黄点，再高就是红点和「离线」。
二维码里带着地址和一把每次启动新生成的 128 位随机密钥，除了页面本身，没这把钥匙什么都不回。起来之后是服务端在后台供着，运行 keepane web 那个终端就空出来了。--read-only 只让看不让打，--keep-key 让二维码每次一样、书签不失效，写 web-start -k 进配置就是开机自己起。自己家网络直接连，在外面就在中间放一层 Tailscale 这类私有网络，绑到它的地址上。时钟页上按 p 也能把这个二维码显示出来，省得回头去翻终端。

把文件递出去

手机页的地址和端口既然已经通了，顺着就能做另一件事：把一个文件或者文件夹丢给手机、丢给旁边那台电脑。

每次分享有自己的随机令牌，不是手机页那把钥匙，所以拿到链接的人只能下这一个东西，别的什么都看不到。默认 24 小时。文件原样发，断了能续传；文件夹边读边打 zip，不跟符号链接。所有东西一律当附件发出，不会被浏览器当网页打开，所以分享一个 html 不会变成在你的地址上跑别人的页面。手机页没开的话，share 会顺带把它开起来。谁在下载、什么时候下完，状态栏都提示一句，看板第三页能管这些分享。

跨电脑

两台电脑上的 pane 也能像同一台上那样互发消息，走的还是 keepane web 那个端口。配对像 ssh-copy-id：每台 server 有自己的一对密钥和一张「允许谁进来」的表，把对方的地址（就是手机扫的那个带密钥的）喂给 link add，一次双向生效。

认的是公钥不是地址，对方从局域网换到 Tailscale 再出现，还是同一台机器。消息到了那边，信封里的 from= 是这台机器和发送的 pane，所以那边 send-message -r 回信就直接回到这里，归在同一个任务下。
配对之后双方什么都还看不到，这是故意的。规则只有一条：谁的 pane 被看，就在谁那台上设置。一共两档：

共享出去的部分对方能看、能发消息，这台电脑的其余部分对它来说不存在。shell 模式的 pane 不收只是共享的机器发来的消息，消息在那里会当命令执行，等于控制这台电脑，那要 --full。普通 HTTP 在局域网里谁都能抓包，所以 --full 只对 Tailscale 地址和本机生效，从局域网地址来的请求只按共享的部分处理，并且会说明原因，确实要的话写 --full --lan。共享和 --full 都只能在 keepane 之外的终端或者 C-b : 里做，不能在 pane 里做，否则 agent 自己就能把别的机器放进来。
0.55 及以前这里是五个开关（--shell、--screen、--panes、--push、--agents），一个一个勾实在说不清谁能干什么，0.77 起只剩上面两档，老配置读不懂了就得重新授权一次。
给了这台 --full 的机器，它的 session 可以直接在这边用。它们仍然是那台机器的东西，只列在那台机器名下：C-b w 的结构图里每台机器一个框，C-b v 按机器分组。

按 Enter 进去，查看、打字、快捷键、主题、复制模式都用本机的，打的字送到对方那个 pane。在这边对它分屏、关闭、改大小、缩放、改名，都交给对方机器去做，做完在这边显示；用按键关东西时会先问一句，并写明在哪台机器上。两边各看各的：对方把缩放挪到别的 pane，不会改这边的选择。pane 不能在两台机器之间搬，在这边对它接管道、录制、保存会被拒绝。
还有两条更轻的路子。keepane link watch 100.64.0.3:7681/%worker 在任何终端里实时看对方一个 pane，开出来的窗口按那个 pane 在对方的名字加机器名命名，比如 raqs@macbook；查看器就是普通 pane 里的普通程序，所以缩放、分屏、复制模式照用，resume 也会把它恢复。keepane link attach 100.64.0.3:7681 work 则是整个进到对方的 session 里，状态栏、前缀键、快捷键全是对方的，所以这个窗口切到 passthrough，按 F12 把键交回本机。
连接和权限是两件事，分开管，这是 0.80 改的：

link disconnect 只管本机这一边，本机不再问它、它的 session 从这边消失，它在本机的权限不变；link connect 恢复
link allow --none 收回它在本机的全部权限，配对还在，但它什么都看不到
link remove 解除配对，两边一起删

所以不想看某台机器就断开它，想挡住它就收回权限。之前这两件事混在一个动作里，断开要两边重新连，很别扭。
对方给了 --full 的话，还能在它那台机器上开 pane：keepane link start <地址> -n helper -- claude，返回它在那边的地址，之后照常发消息，link kill 关掉；程序必须在对方的 agent-commands 白名单里，数量受对方的 agent-pane-limit 限制，而且按这台机器单独计数。
最后是把活儿整个挪过去的两条命令。keepane clone 和 keepane push 单向送提交：打成 git bundle 分块传，对方核对整个文件的 SHA-256 之后才交给 git，提交放进 <本机名>/<分支>；能快进、分支是当前检出的、工作区干净，这三条都满足才顺带把文件也更新了，否则分支不动并说明原因，那边自己合。

send-agents 连对话一起送。Claude Code、Codex、pi 的对话只存在它们运行的那台电脑上，这条把项目和对话一块儿打包过去，对话里的 cwd 改成对方的路径，回复的最后直接写出在那边怎么接着聊：

再送只送变了的部分，对方已有开头的对话只补新增的结尾。对方的东西不会被盖掉。上次送过之后对方改过的文件保留不动，送过去的那份放在旁边叫 <文件名>.from-<本机名>；对方也接着聊过的对话作为一段新对话送过去，换一个新 id。
有一条得说在前面：对话里什么都可能有，agent 读过的文件、跑过的命令和输出。link 的请求签了名，但不加密，所以请在 Tailscale 或者信得过的网里用。设计和每条决定都写在仓库的 docs/design/link.md、link-push.md 和 agent-sync.md 里。

给 agent 配

要让 pane 里的 agent 顺畅收发消息，需要两样东西：一个在它每轮结束时运行 keepane pane-ready -q 的 hook，和一个 MCP 服务端。keepane setup 列出它认识的每家装没装、配没配，setup <agent> --install 替你装上，改之前先备份，只加 keepane 自己那几条。

Claude Code：~/.claude/settings.json 的 SessionStart、Stop，等待 hook 是 Notification
Codex：~/.codex/hooks.json，等待 hook 是 PermissionRequest；新 hook 要在 Codex 里用 /hooks 确认信任一次
Gemini CLI：~/.gemini/settings.json 的 SessionStart、AfterAgent
Cursor CLI：~/.cursor/hooks.json，没有等待 hook；它说回合是被人打断的时候，正在处理的消息记为没做完
opencode：一个插件 ~/.config/opencode/plugins/keepane.js，启动时和 session.idle 时跑
pi：一个扩展 ~/.pi/agent/extensions/keepane.ts；pi 不接 MCP 服务端，它在自己的 shell 里直接用 keepane 发消息

hook 从标准输入上读会话记录的路径和模型，所以这份记录就算这个 pane 的，放在哪都读得到，几周前的 Codex 会话被续上也认得；模型从一开始就显示，不用等记录写出来。没有 hook 的时候照旧去猜：这个目录里最后启动的那个同类 agent。
对 Claude Code、Codex 和 pi，就算 hook 没装，keepane 也能从会话记录看出一轮结束了，最多晚三秒把 pane 设成空闲；用户按 Esc 打断时 hook 不会运行，记录里却有，所以也能跟上。装了 hook 就是立刻生效。这些都按各家文档写的，端到端实测过的只有 Claude Code。
顺带一个坑：Codex 从 0.160、pi 从 1.0 起默认在备用屏幕里画界面，和 vim 一样，输出不进滚动历史，在哪个终端里都一样。想让历史留在 pane 里，Codex 写 alternate_screen = "never"，pi 写 "tuiMode": "regular"。

MCP

keepane mcp 是一个 stdio 的 MCP 服务端，从 KEEPANE_PANE 知道自己服务的是哪个 pane，所以 agent 发出的消息，发送方就是这个 pane，不用它自己记地址。现在 33 个工具：

身份和状态：whoami、list_panes、set_status、set_work_mode
收发：send_message、reply、wait_message、current_message、wait_output
收件箱和追踪：list_messages、trace_message、drop_message、move_message、list_tasks、show_task、query_events
开 pane：create_session、create_window、split_pane、rename_pane、kill_pane
群聊：chat_list、chat_new、chat_join、chat_say、chat_read、chat_who
跨机器：list_links、link_info、read_screen、create_remote_pane、push_repo、list_ssh_hosts

能开 pane 这件事有两道闸。agent 能启动的程序限于 agent-commands，Windows 上默认是 pwsh powershell claude codex；它和它开出来的 pane 一共能开多少受 agent-pane-limit 限制，默认 8。另外在 pane 里面运行 set-work-mode 只能改自己这个 pane，所以 agent 不能把别的 pane 切成会自动执行命令的 shell 模式。这几条是防手滑和防跑飞，不是安全隔离：所有 pane 还是同一个用户的权限，真要隔离得上容器。

重启之后

每个 session 的结构都存成一个文件：有哪些窗口、怎么分的、每块跑的什么命令、在哪个目录，还有屏幕上最后 500 行（save-history all 连整段滚动历史带颜色一起存）。结构一变就存一次，Windows 关机时再整个存一遍，server 会把关机拖住那一瞬间。

startup on 在 Windows 上只写一个用户级的 Run 注册表值，不碰任务计划，server 用 conhost --headless 启动，登录时不会闪出控制台窗口；macOS 上写一个 launchd agent，Linux 上写一个 systemd 用户 unit，后两种还记下当时的 PATH、SHELL 和语言设置，所以 pane 里能找到的程序和你的 shell 一样。
恢复出来的 session、窗口、pane 编号不变。计数器存在存档目录里，同一台机器上一个编号只会给一个 pane，所以脚本或者另一台机器记着 %4，找到的要么就是那个 pane，要么找不到，不会张冠李戴。每个 shell 的命令历史也各自保存，恢复后按 ↑ 翻出来的是这个 pane 自己跑过的命令。
程序当时跑到哪是回不来的，谁也做不到。恢复的是终端这一层：布局、启动命令、目录和屏幕上的文字。agent 自己支持续聊就能接着聊，不支持就得重开。
升级之后已经在跑的 server 不会被换掉，它还是旧程序，session 都在它里面。keepane restart-server 把正在跑的 session 存档、停掉旧 server、起一个新版本的，再把刚才那几个恢复回去，接着的终端会自己重新接上。keepane update 在 Windows 上按当初的安装方式装新版；Scoop 那条要绕一下，Scoop 只在一个应用的程序全都没在跑的时候才更新，而 keepane 的服务端一直在跑，所以 update 先把一份副本挪到 Scoop 目录外面，存好会话、停掉服务端、让 Scoop 装，再带着这些会话用新版本起来，经过写进 update.log。

日常

剩下这些是为「人不在跟前」配的：

C-b w 的结构图把 keepane、session、窗口、pane 排成四排方框，a 一次展开全部，v 切树状和纯文字列表；配过对的机器也在里面，光标停在某台机器的框上时，按键行先写它在本机有什么权限，c 连接、x 断开、R 收回、D 解除配对
C-b u 十秒内找回手滑关掉的 pane 或者窗口，程序还在跑
C-b q 每块显示自己的编号和工作模式，按数字直接跳过去，起过名字的在编号下面显示 %名字
C-b y 把上一条命令的输出取下来，C-b Y 从所有 pane 跑过的命令里挑一条：跳过去、复制它的输出、或者在原地再跑一次；C-b F 给屏幕上所有 pane 里的路径、网址、git hash 标上字母，按小写复制，按大写打开（路径有 code 就用 VS Code 跳到那一行）
C-b / 按 pane、按天翻它打印过的东西，一天一个文件留 30 天，在这个列表里再按 /，一次搜遍每个 pane 的每一天
C-b @ 列出 ssh 去过的机器，正连着的排最前；名单从 pane 里看见的 ssh、~/.ssh/config、known_hosts 和 shell 历史里攒，密码和密钥一概不读不存
C-b e 彩色列出每个 pane 拿到的环境变量；C-b C-t 在每条命令那行的行尾空白处标出开始时间、耗时和成败，不改 pane 宽度
前缀按下去之后手停了半秒，自动弹一个面板告诉你这些键都干什么
默认配色是 paper-dark：底色取这个博客夜里代码块那张纸，正文墨色，一点朱砂留给当前窗口和活动边框，面板和状态栏上每个字的对比度都压到 4.5:1 以上；白天那套叫 paper。手机页上选了电脑的终端跟着变
C-b t 的时钟底下有东西跟着机器动，十三种：监护仪的心跳按 CPU 快慢、字符雨、每个核一根的均衡器、火焰、星野、鲨鱼、盆景、月光下的海、睡着的猫、跑过沙漠的小恐龙、冰面上的企鹅、霓虹网格和城市上空的烟花；数字是真从传感器和进程表读的，keepane 每投递一条消息，心跳抢一拍、水面荡一圈波纹、猫醒三秒。时钟上还有一行黄字写着「等你处理」，跨所有 session 列出等你的 agent 和带提醒标记的窗口
pane 里再跑一个 keepane（ssh 到服务器上那个），F12 把这个 pane 的键全让给它，前缀也让，状态栏写上 passthrough，再按一次收回来

日常那半边不用重新学：前缀 C-b，% " 分屏，[ 进 copy mode，: 命令行，format 串、hook、插件、配置文件的写法照旧，keepane import-config 把现成的 .tmux.conf 过一遍就能接着用。tmux 3.5 的命令表没有落下的，逐条对照在 tmux-parity.md。

装和用

Windows 上 scoop 直接读仓库里的清单，不要管理员权限，另外有 MSI 和 zip；Linux 和 macOS 走 Homebrew。

keepane man 打印完整手册，所有命令、按键、配置、环境变量和 MCP 工具都在里面，测试保证一个不漏；用 Homebrew 装的直接 man keepane。这份手册就是给 agent 读的那份，所以 pane 里的 agent 想查什么自己查。

还差什么

1.0 之前哪些写法保证不变、哪些不保证，写在 docs/compatibility.md 里；群聊在宣布稳定之前都算试验性的
Linux 和 macOS 上还没有 keepane update，只提示怎么升级；带「跳到 pane」按钮的桌面通知也只有 Windows 有
shell 模式靠提示符钩子，所以 cmd 和 sh 暂时不会自己接收消息，只能用 read-message 取
别的机器的 pane 还不能加入群聊；看板里的任务和事件还没上手机页
pane 之间的那几条限制是防手滑的，不是沙箱：所有 pane 跑在同一个用户权限下，真要隔离得上容器

实现

Rust 写的，一个二进制既当客户端也当服务端。第一次运行拉起一个脱离终端的服务端进程，所有 session 归它管，客户端用命名管道（Windows）或者 Unix socket 连上去，管道带着只允许当前用户访问的 DACL，相当于 tmux 那个 0700 的目录。每个 pane 是一个伪终端加一份 vt100 屏幕模型，服务端把可见的 pane、边框和状态栏合成一帧，只把变了的格子发给客户端；客户端写控制台写不过来的时候，服务端不会无限缓冲，直接改成全量重绘。
主循环有 16 ms 的帧率上限。4 个 pane 满速刷屏、挂着一个客户端的时候，服务端 CPU 在一个核以内，同样负载下没有这个上限是 166% 核；按键仍然立刻画出来，不加打字延迟。
Windows 上每个 pane 跑在一个 kill-on-close 的 job object 里，其他系统上整个会话一起挂断，所以关 pane、关 session、服务端退出都会把整棵进程树带走，不留孤儿。平台相关的都收在 src/platform/ 下面，两边模块一一对应，三平台 CI 每次提交跑全量；Windows 上还有一组测试把真的 keepane.exe 塞进一个 ConPTY 里跑，所以控制台那条路不用人坐在键盘前也能测到。
vendor/vt100 是 vt100 0.16.2 加了一处修复：pane 缩小时刚好切到一个宽字符会越界。服务端里任何一条命令 panic 都只记进日志然后接着跑，不会把 session 全丢了。
剩下的都写在 README 和 keepane man 里了，也挂了一份功能一览。上面那张群聊截图里，让我更新视频和图片的也是群里那句话，这篇算是一起办了。
