keepane，AI 时代的终端多路复用

2026-09-28 ·笔记 ·5737 字 ·约 14 分钟 ·阅读 次
Rust终端AgentMCP

Keepane 是一个支持 Windows、Linux 和 macOS 的终端复用工具，用 Rust 实现。
除了 Session、Window 和 Pane，它还管理 Pane 的名称、收件箱、就绪状态和事件记录，供 Shell、脚本与 Agent 之间传递任务。

这篇记录以 0.84 对应的功能为基础，先讲终端如何保活，再讲消息何时交付，以及跨机器操作的权限边界。源码与项目主页在此。

运行结构

运行多个 Agent 时，分屏只解决显示问题。任务可能比客户端连接活得久，新的消息也可能在 Agent 忙碌时到达。Keepane 将进程管理和消息管理放在同一个后台服务中，客户端负责输入与显示，服务端维护实际运行状态。

第一次执行 keepane，程序会自动启动独立 Server。Windows 客户端通过 Named Pipe 连接服务端，Linux 和 macOS 使用 Unix Domain Socket。CLI、Dashboard、MCP 和 Web 界面共用这份状态，不会各自维护一套 Pane。

资源按三级组织：Session 是工作环境，Window 是其中的窗口，Pane 承载真正的终端进程。一个 Session 可以有多个窗口，每个窗口再分成多个 Pane。

C-b w 打开结构图，a 展开全部，v 在结构图、方块树和文字列表之间切换。后文的 C-b 都表示先按 Ctrl-B，再按后面的键。

终端实现

每个 Pane 都有自己的伪终端，Unix 上使用 PTY，Windows 上使用 ConPTY。Shell、编辑器或 Agent 通过伪终端接收输入、输出控制序列，仍然按照交互式终端的方式运行。

服务端用 vt100 终端模型解析各 Pane 的输出，维护光标、颜色、清屏、滚动、备用屏幕、鼠标模式等状态。随后按窗口布局组合画面，再向客户端发送 VT 更新。进程的输出先改变服务端屏幕模型，客户端只负责显示组合后的结果。

Windows 的输入还要处理 Win32 按键事件、PowerShell 的 PSReadLine、IME 和 WSL；Unix 侧则处理终端按键序列、修饰键、Bracketed Paste 和 SGR Mouse。兼容交互程序，既要解析输出，也要正确传递输入。

帧与背压

服务端比较新旧画面，只发送变化的单元格。客户端跟不上时，积压的增量帧会被丢弃，随后用完整重绘恢复一致，避免为缓慢连接无限保存旧画面。

主循环的画面更新有 16 毫秒间隔上限，按键触发的反馈仍即时处理。项目记录中，四个 Pane 持续输出、连接一个客户端时，开启限制后的服务端 CPU 用量在一个核以内，取消限制时约为 166% 核。这是对应负载的结果，不能外推为所有交互程序的性能。

进程回收

Windows 用 Job Object 管理 Pane 的进程树，并在回收时终止进程组；Linux、macOS 通过进程组与终端生命周期清理子进程。关闭 Pane、Session 或 Server 时，需要一并处理其中的程序，避免留下后台进程。

撤销关闭依赖延迟回收：C-b X 关闭 Pane 后，十秒内可以用 C-b U 撤销。超过窗口后，不能再依靠此操作找回原进程。

标识与自动保存

恢复后的 Session、Window 和 Pane 保持原编号。服务端将分配计数器写入存档目录，同一台机器上的编号不重复分配，因此脚本保存的 %4 要么仍指向那个 Pane，要么查找失败，不会因编号复用而落到新 Pane。

Pane 与就绪状态

Keepane 用“Pane as an Actor”描述消息模型：每个 Pane 有独立进程、身份、收件箱和状态，其他 Pane 通过消息与它交互。它借用 Actor 的组织方式，但不会替 Agent 规划任务或选择模型。

Pane 可以通过编号、名称或完整 Session / Window / Pane 地址定位：

完整地址用于消除资源位置的歧义，名称则便于人工和脚本使用。消息接收后怎样处理，由 Work Mode 决定：

模式接收与交付
normal默认模式；进入 Inbox，等待程序主动读取
shell等 Shell 回到提示符，再输入并执行消息内容
ai等 Agent 一轮结束，再将消息作为下一轮输入

工作模式决定交付行为，pane_state 表示此刻的状态，两者不要混用：

idle：空闲；busy：执行中；typing：有人输入但尚未提交。
no-agent：AI 模式的 Pane 回到了 Shell 提示符。
unknown：Shell 模式从未收到提示符标记，例如不具备对应钩子的 CMD。
exited：进程已退出。

Dashboard、手机页面和 #{pane_state} 使用这组状态。用户正在输入时，队列消息继续等待，避免插进尚未写完的命令。

消息交付

发送消息后，服务端先将它放进目标 Inbox，再按工作模式和就绪状态决定交付。目标忙碌时，发送方不用等待，也不应直接向其终端注入下一条输入。

频道协作

一对一消息适合派发任务，多人讨论可以使用频道。成员以称呼和角色加入，频道保存完整对话，Inbox 只接收需要推送的部分。

普通发言只写入频道，由成员用 chat read 主动读取。@称呼 会向目标 Inbox 投递一条消息，同时附上它上次读完后的频道发言，最多二十句。加入时选择 --hear all 才会接收所有发言，两秒内的多句话合并投递。

默认不广播，是为了控制上下文消耗和自动回复循环。五个 Agent 的频道若每句都发给其余四个，每轮都会重复占用四份上下文；收到消息又触发回复时，还可能不断相互唤醒。Shell 模式的成员不接收推送，避免聊天内容作为命令执行，发送方会收到说明。

身份与成员

成员可自行选择称呼和角色；机器、资源地址、Pane 编号与名称、Agent 种类、模型由服务端记录到成员及每条发言上。Pane 只能使用自己的身份。人在 Pane 外通过 Dashboard、独立终端或 C-b : 发言时，显示为 you@<机器名>，无需加入频道。

成员记录比 Pane 生命周期更长。Pane 关闭或服务重启后成员离线，同名 Pane 恢复或其他 Pane 用该称呼重新加入后，可以继续原来的读取位置。主动离开或被移除的成员不会因同名 Pane 出现而自动接回，@ 它会返回未送达说明。

频道与事件日志一起保存，每频道每天一个 JSONL 文件，默认保留三十天。加入、发言和读取也提供 MCP 接口。本文对应版本的群聊仍属实验功能，远程机器上的 Pane 尚不能加入。

追踪与观测

消息追踪用于确认交付和执行经过，Agent Trace 用于查看模型与工具步骤，二者的数据来源不同。前者来自 Keepane 事件，后者主要来自 Agent 自己的会话记录。

消息与事件

trace-message 查询指定消息，-w 等待执行结束。Shell 模式可以附上命令输出与结果。事件日志记录 Pane 创建、消息接收、交付、忙碌、就绪等变化，使用 JSONL，默认保留三十天。排查未执行的任务时，先确认它停在 Inbox、交付还是执行阶段。

用量与费用

Keepane 每两秒读取 Claude Code、Codex、pi 会话记录的增量，提取模型、Token 用量、工具调用、回复次数和上下文占比。CPU、内存来自进程表。Cursor CLI 的对话不可读，只展示 CPU、内存和 Hook 报告的模型。

pi 直接采用记录中的费用；其他模型按 LiteLLM 公开价目表，对新输入、缓存读写和输出分别估算。这表示等量调用走 API 的标价，不等于 Claude Max 或 ChatGPT Pro 等订阅的实际账单。未能计价的模型不会计入金额，数字后显示 + 表示还有未计价部分。

Dashboard

运行 keepane dashboard，或在 Session 中按 C-b v。第一页将 Pane、Inbox、Tasks 和详情放在一起，可以沿消息找到关联任务，也可以查看当前 Pane 的工作目录、PID、运行时间、屏幕、滚动历史和事件。

Inbox 支持删除、恢复、排序和置顶。管理快捷键包括 s 发消息、r 改名、m 改工作模式、R 标记就绪、o 进入 Pane、x 关闭；关键操作会再次确认。

< 和 > 切换三页：第一页管理 Pane、消息和任务，第二页是频道，第三页展示本机分享的文件、有效期、下载次数和二维码。

窗口宽度超过 150 列时，左侧增加目录浏览与系统信息。目录取所选 Pane 的工作目录，选中文件可预览内容；CPU、内存、交换区、磁盘、网络、温度、功率和电池每秒刷新。底栏按 L 管理配对机器的连接、权限和配对关系。

MCP 与 Hook

keepane mcp 通过标准输入输出提供工具，使用 KEEPANE 和 KEEPANE_PANE 环境变量确定当前 Server 与所属 Pane。Agent 无须在提示词中手写自己的 Pane 编号。

本文对应版本有 33 个工具，覆盖以下操作：

身份与状态：whoami、list_panes、set_status、set_work_mode。
消息：send_message、reply、wait_message、current_message、list_messages、drop_message。
追踪：trace_message、list_tasks、query_events、wait_output。

资源：create_session、split_pane。
频道：chat_list、chat_join、chat_say、chat_read。
远程：list_links、read_screen、push_repo。

MCP 调用和 CLI 使用同一套资源、消息与权限检查。Agent 可以修改自己的 Work Mode，但不能借自己的 MCP 身份把其他 Pane 改成自动执行命令的 Shell 模式；允许创建的进程种类和 Pane 数量也可配置。

查看与控制

获得远程完整权限后，可以在本机结构图或 Dashboard 中按机器浏览对方 Session。输入、分屏、关闭、调整大小、缩放和改名请求交给资源所在机器执行，本机显示结果。

也可以单独使用：

手机与飞书

keepane web 启动 Web 管理界面并显示二维码，手机通过同一 Wi-Fi 或 Tailscale 访问。页面可以查看 Session、Pane、状态和 Inbox，并向 Pane 发消息。二维码携带地址与每次启动重新生成的 128 位随机密钥，管理 API 需要该密钥。

顶栏气泡按钮打开频道，和 Dashboard 共用数据，输入 @ 时列出成员。网格模式显示每个 Pane 最后四行输出，手机竖屏一行两格。

回形针按钮将文件上传到 Pane 目录，默认存入 keepane-uploads，其中生成内容为 * 的 .gitignore；同名文件不会覆盖。当前手机页面尚未提供 Dashboard 的任务和事件视图。

飞书消息

普通 HTTP 页面无法提供系统通知，锁屏后浏览器也可能暂停页面。飞书 / Lark 集成由 Keepane 主动建立长连接，不要求本机开放入站端口。

回复“在等你”的通知时，内容直接输入对应 Pane：1、y、esc、enter 等单键按原样发送，其他文字输入后回车。回复普通通知则走 send-message。命令还包括 /panes、/to <pane> <文字>、/key <pane> <按键>、/screen <pane>。

机器人仅接受白名单账号的单聊。默认只向 Agent 发送按键，只向 Agent 或 normal Pane 发消息。允许无 Agent 的 Pane 接收按键，或允许 Shell 模式接收消息，均需要 --shell 授权；/screen 会将屏幕发送到飞书服务器，需要 --screen。这些授权同样只能在 Pane 外设置。

需要共同讨论时，再加入同一频道，避免手工在多个 Inbox 间转述。任务分工、验收标准和是否重试由人或上层 Agent 决定；Keepane 保存身份、队列、就绪信号和追踪信息。共享代码目录中的并发修改仍要另行协调。

使用边界

Pane 之间拥有独立终端，但通常共享同一操作系统用户权限，不能当作安全沙箱。进程白名单、数量限制和远程授权可限制管理入口，隔离不可信程序仍需操作系统、容器等其他机制。

自动交付还依赖可靠的就绪信号。本文对应版本中，CMD 和 sh 没有相应提示符 Hook，Shell 模式不会自动接收消息，需要主动 read-message。其他交互程序也不应仅凭停止输出就改为空闲。

恢复布局、交付消息、业务任务完成分别有自己的条件。检查长任务时，把 Pane 进程、消息追踪、Agent 会话和实际文件结果一起看，才能知道工作停在哪里。

后台任务还在不在，先看进程，再看那条消息。
