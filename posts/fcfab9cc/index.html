Agency Agents：角色文件的转换与分发

2026-08-12 ·笔记 ·1164 字 ·约 3 分钟 ·阅读 次
LLMAgentPrompt

Agency Agents 是一套可安装到多种编码工具中的角色提示文件，采用 MIT 协议。
角色文件规定领域检查项、工作方式和产出格式，转换与安装脚本再适配各工具的配置格式。
下面区分角色内容、分发契约与目录校验，避免把角色名称误当作模型新增的能力。

定位

本文对应 checkout 有 270 个角色，按 17 个分部组织，覆盖工程、设计、安全、测试、销售以及 GIS、游戏开发等领域。每个角色以 Markdown 保存，front matter 描述名称、简介和展示属性，正文定义任务范围、规则与产出要求。

角色差异需要看正文。例如网络工程师包含设备配置与排障检查项，销售角色可能使用 MEDDPICC 评分框架。名称本身不能说明专业深度，也不能证明模型已经具备相应知识。

角色文件

Code Reviewer 的示例将评审意见分为阻断、建议与细节问题，每条意见要求说明原因和修改方式，并规定一轮给全意见等交互方式。

这种文件适合固定检查单和交付格式，使同类任务有较一致的执行顺序。模型、工具与可见资料仍来自宿主环境，角色提示不会自动增加外部系统访问权限或事实知识。

分发管线

同一份角色需要转换为不同工具识别的配置，分发脚本负责维持源文件与安装产物的对应关系。

角色的分发管线：一份 markdown 源，按契约渲染成各工具认得的形状

（交互版，可缩放、可播放数据流轨迹。）

tools.json 给 16 个工具各立一份契约：渲染格式、安装形态、探测目录、落盘路径。
convert.sh 按契约把角色渲染进 integrations/：Claude Code 原样 markdown 落 .claude/agents/，
Codex 转 TOML，Cursor 转 .mdc 规则，Kimi 一个角色两件套（yaml + system.md），

OpenClaw 每角色输出 SOUL、AGENTS、IDENTITY 三个文件。
安装形态分三种：per-agent 一角色一文件；roster 全员拼成一个大文件（Aider 的 CONVENTIONS.md、Windsurf 的 .windsurfrules 走这条）；
plugin 是构建出来的插件工件（Hermes 路由插件）。
install.sh 是个交互向导：自动探测机器上装了哪些工具，按分部或单个角色挑着装，支持 dry-run；

另有一个桌面 App（独立仓库）读同一份目录，点一下装、自动更新。

目录治理

目录治理分别管理角色分部和工具契约，CI 再检查各消费方使用的清单是否一致。

两份事实源与一致性闸：目录、脚本、App 消费同一份目录，CI 负责对账

（交互版）divisions.json 管分部，tools.json 管工具，
转换与安装脚本里各持一份清单，CI 逐项对账：目录里多了个分部而 json 没登记、脚本清单跟契约对不上，构建直接红。
还有一道原创性检查，专防复制粘贴改个名就提交的角色。
这些检查能发现目录、契约与脚本之间的漂移，但不评判角色的专业内容是否正确。

安装

适用限制

角色改变模型的任务约束与输出方式，不能替代专用工具、资料或人工复核。安装前应阅读正文，确认检查项具体、适用条件清楚，并用自己的任务验证。

批量安装还会增加选择与上下文成本。按文件分发的工具会出现大量候选；roster 形式则把多个角色合并到一份规则文件，可能在每次会话加载。宜只安装需要的分部或角色。

本文对应文档还记录了 OpenCode 超过 119 个角色时可能静默丢弃的上游问题。该限制属于版本相关行为，不能作为其他工具或后续版本的通用上限。

转换脚本的 CI 保证仓库内部契约一致，宿主工具升级后，配置格式和目录约定仍需重新验证。与 Skill Shelf 相比，这里主要分发角色规程，后者还涉及技能版本、服务配置与路由。

先挑一个角色跑熟，再扩大安装范围。
